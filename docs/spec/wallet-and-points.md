# 积分与充值余额

## 范围与状态

定义积分获取、充值余额、积分购买、资料消费、奖励和退款的目标业务。本文记录 owner 于 2026-10-23 确认的规则，未决部分单列；当前没有钱包、支付接口或真实资金处理。

## 账户与转换

| 项目 | 已确认规则 |
| --- | --- |
| 积分 | 独立账户，可通过多种业务活动获得，也可用余额购买 |
| 充值余额 | 独立账户，用于支持的余额消费和购买积分，不自动过期 |
| 账户间转换 | 允许余额购买积分，不允许积分换回余额 |
| 转赠与提现 | 积分和余额均不提供用户间转赠或提现 |
| 积分有效期 | 支持长期和限时积分，具体按规则配置 |
| 来源展示 | 用户能区分获得、消费、到期和退款，不把即将到期积分显示成永久有效 |

购买积分与人民币退款是不同操作，不能以积分余额计算用户可退现金。余额购买积分时，向用户显示所花余额、所获积分及有效期，由用户确认。

## 积分获取与上传奖励

以下获取方式均已确认纳入可用业务范围，奖励数值可以在管理界面配置：

| 获取方式 | 对应的业务事件 |
| --- | --- |
| 每日签到 | 完成当天签到 |
| 学生认证 | 完成符合奖励条件的学生认证 |
| 有效评课 | 发布符合规则的有效评课 |
| 上传资料 | 资料上传并通过审核 |
| 优质内容 | 内容被认定为优质 |
| 存储贡献 | 持续贡献符合条件的存储容量 |
| 活动 | 完成活动规定的条件 |
| 管理员发放 | 管理员向指定用户发放积分并说明原因 |

各方式的启停、奖励额度、可获次数、周期和限时积分期限需要有明确规则，不能仅因反复点击、重复通知或重复查看结果而重复发放同一奖励。有效评课、优质内容和存储贡献的具体认定条件尚待设定。

上传者奖励与资料销售分开。用户解锁资料所支付的积分或余额由平台消耗或收取，不自动转给上传者，也不预设销售分成。

## 资料定价与解锁

管理员可将需解锁资料设置为仅积分、仅余额或积分与余额二选一，并配置各自价格。二选一表示选择一种方式完成全额解锁，不自动表示可混合抵扣，也不表示两种价格必须按固定汇率等值。

用户已经通过管理员范围、单独授权或群体权益取得访问权时，直接下载，不再次付费。一次成功解锁该资料后长期可下载，并包含其后续版本；重复点击、重新下载或获取新版本不重复收费。完整授权来源见[资料规格](resource-sharing.md)。

余额或积分不足时说明所缺额度；扣费成功但未取得访问权不能显示整个操作成功。费用、所用账户和解锁结果应能在用户记录中对应查看。

## 退款规则

未消费的充值余额可以申请退款。余额购买积分后，不自动把积分换回余额。资料解锁通常不退；重复扣费、无法获得承诺的资料等异常，可由管理员按实际情况退回原支付账户：积分支付退积分，余额支付退余额。法定应退款情形按相应要求处理。

退款完成后处理该笔消费对应的解锁权益；用户若仍有单独授权、会员权益等其他有效来源，仍可按该来源访问。积分奖励是否因关联内容撤回而追回，不能与消费退款混为一项操作，具体奖励追回规则待确认。

## 原路与人工退款

| 阶段 | 用户与管理员能看到的结果 |
| --- | --- |
| 提交申请 | 用户选择相关充值或消费，说明原因，显示等待处理 |
| 审核 | 管理员决定是否退款、金额或积分数量及退款方式，反馈原因 |
| 原路退款 | 收款渠道支持时向原支付路径退款；显示处理中或实际完成结果 |
| 补充收款信息 | 不能原路退回时，用户提交收款码或收款账户，显示等待人工处理 |
| 人工退款 | 管理员依据申请向所确认收款方式付款并更新实际结果 |
| 已完成或失败 | 用户能区分已退款、仍待处理和退款失败，知道后续处理状态 |

提交收款信息、管理员批准与实际付款完成是三个不同结果。同一笔申请只能退款一次；原路退款结果不明时，先核实结果再安排人工退款，避免双重退款。消费退回账户与将充值退回外部收款方式分别记录，不能用一次手动改余额伪装两种动作都已完成。

## 管理界面

管理员需要查看积分和余额变动、配置积分奖励与期限、设置资料解锁价格、处理退款申请与人工付款结果。资料逐用户授权、群体权益配置仍在资料访问管理中维护。用户需要账户总览、获取和消费明细、积分到期提示、购买积分及退款申请与进度入口。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| WP-01：用户获得积分或充值余额 | 进入对应账户，不能把两者混成可随意提现的一笔钱 |
| WP-02：用户用余额购买积分 | 扣减确认的余额、增加约定积分，并展示期限；无反向兑换入口 |
| WP-03：同一奖励事件重复处理 | 不重复发放该次奖励 |
| WP-04：资料支持积分或余额解锁 | 用户选择其中一种，已有访问权时不扣费 |
| WP-05：已解锁资料出现后续版本 | 长期访问权继续覆盖，不重复收费 |
| WP-06：积分支付的异常消费退款 | 退积分；不转换为可退现金的余额 |
| WP-07：原充值渠道无法原路退款 | 引导补充收款码或账户，进入人工退款流程 |
| WP-08：用户已提交人工收款信息但尚未付款 | 显示等待处理，不显示退款成功 |
| WP-09：退款完成但用户仍有另一有效授权 | 仅处理退款对应权益，不撤回独立存在的授权 |

## 待确认事项

余额计价单位、积分扣除顺序、已到期积分的退款有效期、充值渠道、积分售价与奖励默认值、奖励追回、会员购买与套餐规则尚待明确。限时积分到期、充值退款和资料下架的交互需要在实现前覆盖；不能把“业务文档完整”表述为真实支付验收完成。
