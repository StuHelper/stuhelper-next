# 账户与交易的公共对接说明

## 用户体验

个人中心提供积分与 Ivory 入口，展示本人可查看的账户摘要、明细及申请进度。业务页面展示服务返回的可选交易方式、需支付内容和实际结果。用户确认后才提交交易请求。

重复点击或请求重试不得重复收费。页面区分已提交、处理中、成功和失败，不能将请求受理显示成已完成付款或退款。未配置或不可用的交易能力不向用户提供可执行入口。

## 会员套餐与商品退款

用户套餐列表只展示启用且至少配置一种正数价格的套餐。页面同时读取 resources 的实际覆盖范围，没有覆盖规则的套餐不可购买。用户选择积分或 Ivory 账户，全价购买或续费；余额不足返回差额。

同套餐续费延长有效期间。购买、续费和管理员授予保存当时的套餐名称快照，后续改名或停售不改写已购记录。套餐按读取版本保存，停售保留条款和已购期间。

管理员直接授予会员时填写原因，资料覆盖仍按 resources 当前规则判断。商品退款要求管理权限并记录原因；资料解锁整单退款，会员退款可部分退但不超过原价。会员退款结束对应剩余期间，保留后续期间时长。

## 退款收款资料

用户可在退款申请中提交收款方式、户名和账号，也可稍后补充。资料与退款记录关联，使用 AES-256-GCM 加密，随机 nonce 与账号、订单绑定的附加认证数据防止密文被调换。日志、幂等结果与审计不保存收款原文。

Admin 只有在管理员点击查看后才读取完整收款资料，除管理权限外另需 billing.refund-payee-read，并在审计提交成功后返回。无资料时明确提示未提交，权限不足或审计失败不返回字段。

收款资料默认至少保留三年，清理跳过未完成退款和 legal_hold。实际财务保留期限仍待负责人确认，真实业务启用前按确认结果配置。密钥及 relay 配置见[后端交易配置](../guide/backend-commerce.md)。

## 权限与接入

余额、交易与收款资料仅按本人或获授权管理员的权限返回。公开模块不读取私有账务数据库，不把交易载荷写入通用事件或日志。服务不可用时保留既有事实，明确返回当前不可执行。

具体货币、计价、奖励、购买与退款规则维护在 [私有账务规格](https://github.com/StuHelper/stuhelper-billing/blob/develop/docs/spec/wallet-and-points.md)，资料交易关系见 [私有权益规格](https://github.com/StuHelper/stuhelper-billing/blob/develop/docs/spec/resource-entitlements.md)。

| 场景 | 预期结果 |
| --- | --- |
| WP-19 | 充值通知验签，重复和并发只入账一次，事务失败不留下部分余额，未确认订单不阻塞后续处理 |
| WP-20 | 退款结果不明时保留冻结，明确失败释放，人工付款完成后记录实际结果 |
| WP-21 | 奖励按可信事件与历史规则处理，重复不发放，追回和后续抵扣按所属账本执行 |
| WP-22 | 异常订单退款按私有规则计算，包括已到期但未消费的积分，退回原批次且不超过原价 |
| WP-23 | 注销结清后禁止继续入账，未登录和越权请求被拒绝 |
| WP-18 | 注销前核对资产和待处理交易，结清原子清零积分并冻结后续账务，响应丢失后查询实际结果 |

## 客户端场景

| 场景 | 预期结果 |
| --- | --- |
| WP-CLIENT-01：Web 会员套餐 | 显示实际覆盖范围，无覆盖规则的套餐不可购买 |
| WP-CLIENT-02：Web 购买或续费会员 | 从所选账户支付全价，余额不足显示差额 |
| WP-ADMIN-01：Admin 套餐维护 | 按读取版本保存；停售保留条款与已购期间 |
| WP-ADMIN-02：Admin 覆盖范围 | 按读取修订保存，目录精确匹配不含子目录 |
| WP-ADMIN-03：Admin 授予与退款 | 直接授予会员并记录原因；资料解锁整单退款，会员退款不超过原价 |
| WP-ADMIN-04：Admin 查看收款资料 | 仅在点击后读取，需单独权限且审计成功才返回；未提交时明确提示 |
