# 积分与 Ivory 余额

## 范围与状态

本文定义积分获取、Ivory 充值、积分购买、资料消费、奖励和退款。项目负责人于 2026-10-23 确认下述规则，剩余选择在文末列出。

## 账户与转换

| 项目 | 已确认规则 |
| --- | --- |
| 积分 | 独立账户，可通过多种业务活动获得，也可用余额购买 |
| Ivory 余额 | 独立账户，以 Ivory 计价，用于支持的余额消费和购买积分，不自动过期 |
| 账户间转换 | 允许余额购买积分，不允许积分换回余额 |
| 转赠与提现 | 积分和余额均不提供用户间转赠或提现 |
| 积分有效期 | 支持长期和限时积分，具体按规则配置 |
| 来源展示 | 用户能区分获得、消费、到期和退款，不把即将到期积分显示成永久有效 |

购买积分与人民币退款是不同操作，不能以积分余额计算用户可退现金。余额购买积分时，向用户显示所花余额、所获积分及有效期，由用户确认。

## Ivory 命名与充值币种

充值余额使用 Ivory 作为计价单位，名称取“象牙塔”的校园意象。Ivory 是站内账户单位；积分仍称“积分”，不因余额命名改变积分的用途或兑换方向。

| 充值币种 | 已确认规则 | 尚未确定 |
| --- | --- | --- |
| CNY | 人民币充值按 1 CNY = 1 Ivory 入账，例如充值 10 CNY 得到 10 Ivory | 具体支付渠道、充值额度与到账流程 |
| USDT | 纳入需要支持的充值方式，到账余额同样以 Ivory 表示 | 汇率来源与时点、报价有效期、网络、手续费、到账确认和退款折算 |

USDT 的兑换规则后续确认。充值界面分别显示支付币种、支付金额和将获得的 Ivory 数量，使用已经确认的兑换规则报价。

## 积分获取与上传奖励

以下获取方式均已确认纳入可用业务范围，奖励数值可以在管理界面配置：

| 获取方式 | 对应的业务事件 |
| --- | --- |
| 每日签到 | 完成当天签到 |
| 学生认证 | 完成符合奖励条件的学生认证 |
| 有效评课 | 发布符合规则的有效评课 |
| 上传资料 | 资料上传并通过审核 |
| 优质内容 | 内容被认定为优质 |
| 存储贡献 | 持续贡献符合条件的存储容量 |
| 活动 | 完成活动规定的条件 |
| 管理员发放 | 管理员向指定用户发放积分并说明原因 |

各方式的启停、奖励额度、可获次数、周期和限时积分期限需要有明确规则，不能仅因反复点击、重复通知或重复查看结果而重复发放同一奖励。有效评课、优质内容和存储贡献的具体认定条件尚待设定。

上传者奖励与资料销售分开。用户解锁资料所支付的积分或余额由平台消耗或收取，不自动转给上传者，也不预设销售分成。

## 积分消费顺序

消费先扣除有效期最早结束的可用限时积分，再扣长期积分。已经过期的积分不参与可用余额或扣除。不同来源的积分保持各自原有有效期，消费和退款不把限时积分自动改成长期积分。

## 资料定价与解锁

管理员可设置仅积分、仅余额或两者二选一的解锁方式，并分别配置价格。用户选择一种方式支付全部价格。混合抵扣和两种价格之间的换算关系尚未定义。

普通用户下载资料必须保持有效学生资格；单独授权、会员权益和购买解锁都不能豁免该条件。管理员仅在自己的管理范围内例外。满足学生资格且已经取得有效访问权的用户直接下载，不再次付费。

一次成功解锁的权益长期保留，并覆盖该资料后续版本；学生资格失效时暂停普通用户下载，不因此抹去解锁权益，恢复资格后无须重复购买。重复点击、重新下载或获取新版本不重复收费。完整条件见[资料规格](resource-sharing.md)。

余额或积分不足时说明所缺额度；扣费成功但未取得访问权不能显示整个操作成功。费用、所用账户和解锁结果应能在用户记录中对应查看。

## 退款规则

未消费的充值余额可以申请退款。余额购买积分后，不自动把积分换回余额。资料解锁通常不退；重复扣费、无法获得承诺的资料等异常，可由管理员按实际情况退回原支付账户：积分支付退积分，余额支付退余额。法定应退款情形按相应要求处理。

退还积分遵循原积分类型与原有效期，以实际退款到账时判断是否仍可用。原有效期已经届满的部分不返还为可用积分，不续期、不转为长期积分，也不增加退款宽限期；尚未过期的部分保留原到期时间，到账后期限届满仍照常失效。长期积分退款后仍为长期积分。

退款完成后处理该笔消费对应的解锁权益；用户若仍有单独授权、会员权益等其他有效来源，仍保留该来源的权益，但普通用户实际下载仍需有效学生资格。积分奖励是否因关联内容撤回而追回，不能与消费退款混为一项操作，具体奖励追回规则待确认。

## 原路与人工退款

| 阶段 | 用户与管理员能看到的结果 |
| --- | --- |
| 提交申请 | 用户选择相关充值或消费，说明原因，显示等待处理 |
| 审核 | 管理员决定是否退款、金额或积分数量及退款方式，反馈原因 |
| 原路退款 | 收款渠道支持时向原支付路径退款；显示处理中或实际完成结果 |
| 补充收款信息 | 不能原路退回时，用户提交收款码或收款账户，显示等待人工处理 |
| 人工退款 | 管理员依据申请向所确认收款方式付款并更新实际结果 |
| 已完成或失败 | 用户能区分已退款、仍待处理和退款失败，知道后续处理状态 |

提交收款信息、管理员批准与实际付款完成是三个不同结果。同一笔申请只能退款一次；原路退款结果不明时，先核实结果再安排人工退款，避免双重退款。消费退回账户与将充值退回外部收款方式分别记录，不能用一次手动改余额伪装两种动作都已完成。

## 管理界面

管理员需要查看积分和余额变动、配置积分奖励与期限、设置资料解锁价格、处理退款申请与人工付款结果。资料逐用户授权、群体权益配置仍在资料访问管理中维护。用户需要账户总览、获取和消费明细、积分到期提示、购买积分及退款申请与进度入口。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| WP-01：用户获得积分或充值余额 | 进入对应账户，不能把两者混成可随意提现的一笔钱 |
| WP-02：用户用余额购买积分 | 扣减确认的余额、增加约定积分，并展示期限；无反向兑换入口 |
| WP-03：同一奖励事件重复处理 | 不重复发放该次奖励 |
| WP-04：资料支持积分或 Ivory 解锁 | 用户选择其中一种；符合学生资格且已有访问权时不扣费 |
| WP-05：已解锁资料出现后续版本 | 解锁权益继续覆盖；符合当前下载条件时不重复收费 |
| WP-06：积分支付的异常消费退款 | 未过期部分按原类型、原有效期退回；过期部分不恢复为可用积分，不转换为 Ivory |
| WP-07：原充值渠道无法原路退款 | 引导补充收款码或账户，进入人工退款流程 |
| WP-08：用户已提交人工收款信息但尚未付款 | 显示等待处理，不显示退款成功 |
| WP-09：退款完成但用户仍有另一有效授权 | 仅处理退款对应权益，不撤回独立存在的授权 |
| WP-10：CNY 充值成功，充值金额为 10 CNY | 入账 10 Ivory，明细区分支付币种与站内计价单位 |
| WP-11：同时有多批限时积分和长期积分 | 先扣最早到期的可用限时积分，再扣长期积分 |
| WP-12：申请退款时积分未过期，但实际到账时原期限已过 | 不恢复为可用积分，不延长有效期 |
| WP-13：普通用户学生资格失效，已经购买资料 | 暂停下载但保留解锁权益；恢复资格后无须重复购买 |

## 待确认事项

Ivory 的显示精度、充值渠道及额度、USDT 兑换与到账规则、积分售价与奖励默认值、奖励追回、会员购买与套餐规则尚待明确。未满足学生资格时是否允许先购买受限资料，以及已购后资格失效是否影响退款判断，需另行确认。实现时需要验证限时积分到期、充值退款与资料下架相互影响的场景，实际支付结果在开发记录中单独记录。
