# 社交与内容治理

## 范围与适用情况

首期建议提供动态、关注、评论/回复、点赞、收藏、屏蔽、举报、站内通知和按时间排序的信息流。私信、群聊、直播和复杂推荐等待独立产品设计。本文是待实现的行为提案。

## 内容引用与互动

动态可以引用课程、开课、教师、评价和资料的稳定标识。展示前检查目标存在性与可见性；目标被限制或删除时显示占位，不继续返回旧正文、附件或敏感快照。

评论目标类型由受控注册表声明，目标模块负责权限判断。点赞、收藏、关注的重复请求按相同用户/目标和动作语义处理，重试不重复增加计数。通知只在业务事实已提交后生成，同一事件不重复通知；用户可管理通知偏好和已读状态。

## 发布、审核与隐私

内容生命周期区分草稿、待审核、已发布、受限、已下架、已删除。审核模块管理举报、处置与申诉，内容所属模块执行状态变更；审核员须同时满足动作 capability 和学校/版块 scope。

匿名展示身份与内部审计身份分开。若目标内容允许匿名，API、搜索、文件路径和通知均不得泄露作者真实标识；内部审计仍需可归责且限制访问。个人主页仅披露已允许公开的内容，不公开学生资格证据、手机号或原始身份字段。

屏蔽、资格到期、撤权和下架应在读取/互动时生效。信息流与搜索可使用最终一致投影，但必须在返回前过滤当前不可见内容。取消关注和退出账号后的通知/展示行为需遵循实际用户选择。

## 验收场景

| 场景 | 初始条件与动作 | 预期结果 |
| --- | --- | --- |
| SOC-01 | 动态引用已公开资料，随后资料被下架 | 动态保留可解释占位，卡片、搜索和通知不泄露旧资料 |
| SOC-02 | 相同点赞/收藏提交重试 | 最终只有一条有效关系，计数不重复 |
| SOC-03 | 匿名评价被评论、搜索并生成通知 | 所有对外入口保持匿名，内部审计可按权限追溯 |
| SOC-04 | 不在目标学校/版块范围的审核员处理举报 | 拒绝，不改变内容状态，记录受限审计 |
| SOC-05 | 关闭 social 后查看课程与评价正文 | 核心内容仍可用，评论/关注入口及直连操作不可用 |
| SOC-06 | 通知投递失败后重试 | 业务发布事实保留，重试不重复发布内容或生成通知 |

## 待确认事项与关联

关注/屏蔽的具体可见性政策、通知默认偏好、匿名允许范围和审核前置策略在对应功能实施前确认。机制见[内容设计](../design/academic-content.md)，任务见[重写路线](../development/rewrite-roadmap.md)。
