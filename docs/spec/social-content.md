# 社交与内容治理

## 范围与适用情况

项目负责人于 2026-10-24 明确将社交动态、分区、关注、私信和站内群聊等独立延期。本轮继续课程评价与资料业务，以及已经确认的其他校园功能。课程评价自身的回复、投票、收藏和举报属于 reviews，不依赖本模块。

以下保留早期方案作为后续讨论材料，不是已确认的首期范围，也不作为本轮业务迁移的未决阻断。再次启动社交设计时，重新确认内容范围、匿名政策、操作资格和治理规则。

## 内容引用与互动

动态可以引用课程、开课、教师、评价和资料的稳定标识。展示前检查目标存在性与可见性；目标被限制或删除时显示占位，不继续返回旧正文、附件或敏感快照。

评论可以关联的目标类型在服务端注册表中声明，目标模块负责权限判断。点赞、收藏、关注的重复请求按相同用户/目标和动作语义处理，重试不重复增加计数。通知只在业务事实已提交后生成，同一事件不重复通知；用户可管理通知偏好和已读状态。

## 发布、审核与隐私

内容生命周期区分草稿、待审核、已发布、受限、已下架、已删除。审核模块管理举报、处置与申诉，内容所属模块执行状态变更；审核员需要具备对应操作权限（capability），且目标属于获准的学校或版块范围（scope）。

匿名展示身份与内部审计身份分开。若目标内容允许匿名，API、搜索、文件路径和通知均不得泄露作者真实标识；后台保留作者关联，供获授权的管理员处理内容和举报。个人主页仅披露已允许公开的内容，不公开学生资格证据、手机号或原始身份字段。

屏蔽、资格到期、撤权和下架应在读取/互动时生效。信息流与搜索可使用最终一致投影，但必须在返回前过滤当前不可见内容。取消关注和退出账号后的通知/展示行为需遵循实际用户选择。

## 验收场景

| 场景 | 初始条件与动作 | 预期结果 |
| --- | --- | --- |
| SOC-01 | 动态引用已公开资料，随后资料被下架 | 动态保留可解释占位，卡片、搜索和通知不泄露旧资料 |
| SOC-02 | 相同点赞/收藏提交重试 | 最终只有一条有效关系，计数不重复 |
| SOC-03 | 匿名评价被评论、搜索并生成通知 | 所有对外入口保持匿名，内部审计可按权限追溯 |
| SOC-04 | 不在目标学校/版块范围的审核员处理举报 | 拒绝，不改变内容状态，保存仅获授权人员可查看的操作记录 |
| SOC-05 | 关闭 community 后查看课程与评价 | 课程、评价及其回复/投票/收藏仍可用，社交动态与关注入口不可用 |
| SOC-06 | 通知投递失败后重试 | 业务发布事实保留，重试不重复发布内容或生成通知 |

## 待确认事项与关联

关注/屏蔽的具体可见性政策、通知默认偏好、匿名允许范围和审核前置策略在对应功能实施前确认。机制见[内容设计](../design/academic-content.md)，任务见[重写路线](../development/rewrite-roadmap.md)。
