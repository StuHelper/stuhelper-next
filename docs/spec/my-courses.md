# 我的课程与课表

## 范围

该业务已确认保留：用户查看本人某学期课程、授课教师、上课时间和地点，并进入相关课程内容。旧项目提供学校数据读取与展示，本次没有确认选课、退课、排课或成绩写入业务。

## 目标行为

用户可从个人中心进入我的课程，按学期查看课程列表和课表。每条课程保留能够取得的课程、教学班、教师、时间、地点信息；缺失字段显示未提供，不把未知时间或地点编造为默认值。

能够关联到课程目录时，用户可继续查看课程详情、评价和资料；能够关联到教师时，可进入教师开课列表。关联尚未建立时仍能理解学校提供的课程记录，不因缺少平台教师档案而隐藏整门课程。

页面区分尚无课程数据、该学期确无课程以及数据加载失败。页面显示来源与更新时间。用户可导入已接入的学校课程，也可手动添加和更正个人课程。个人修改作用于本人日程。评课资格采用可信教务导入的选课记录，个人日程与选课证据分别保存。

保留历史学期，支持按学期查看周课表、导出日历与可选上课提醒。导入与现有个人修改冲突时，由用户选择保留或替换，不能静默覆盖。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| MC-01：本人当前学期存在课程 | 展示课程、教师和已知时间地点，支持课程与课表视图 |
| MC-02：切换学期 | 展示所选学期，不混入其他学期的课程 |
| MC-03：课程未关联到平台教师或缺少地点 | 保留已有课程信息，未知项明确显示 |
| MC-04：学校数据暂不可用 | 说明数据状态，不把故障显示成用户没有选课 |
| MC-05：导出单双周课表 | 日期与时区转换正确，UID 稳定；时间或作息缺失返回 schedule_incomplete |
| MC-06：管理员更正学校作息 | 检查学校范围与修订，重复写入不重复产生审计，事务失败全部回滚 |

## 配置与后续事项

学校按实际接入能力开放，同步频率由后台配置。日历采用 iCalendar；个人日程编辑、上课提醒与真实学校数据验收仍待完成。

## 结构化排课与周视图

catalog 的 schedule_time 包含星期 weekday、起止节次 start_period/end_period 和周次集合 weeks。星期从周一的 1 到周日的 7，节次范围为 1—30，周次范围为 1—60，周次不得重复。单双周以周次集合表达，周视图按所选周次与星期展示。

导入支持结构化字段，也识别“周一 第1-2节 第1-16周(单)”格式，并在预览中展示解析结果。原始 time_text 始终保留；无法解析的文本不生成结构化时间，显式无效结构返回 invalid_input。缺失时间或作息时显示“未提供”。

GET /api/v1/catalog/me/schedule 必须传 term_id，只查询认证请求人的有效选课。响应包含课程 ID 与名称、教学班、教师、地点、时间原文、结构化排课及可用作息。缺少教师列表的历史记录仍可读取，作息缺失时省略 timetable。

每页最多 100 条选课，每条最多 100 个排课，每页最多 1000 个排课。超限返回 unavailable，调用方可缩小分页；接口不截断结果。查询按学期隔离，不允许指定其他账号读取课表。

## 日历导出与学校作息

GET /api/v1/catalog/me/schedule/calendar 导出所选学期的完整 iCalendar，最多处理 100 条选课和 10000 个事件，超限返回 unavailable。没有选课时返回空日历。

任一选课缺少排课、结构化时间或所需作息时，导出返回 HTTP 422 schedule_incomplete。夏令时造成无效或歧义时间时也返回该错误，不能静默遗漏课程或推测时间。

日历按星期和周次展开日期，用学校 IANA 时区转换为 UTC DTSTART 与 DTEND。UID 由请求人、学校、学期、教学班、排课 ID 和周次确定，调整作息保持 UID。文本转义、CRLF 与字节折行遵循 iCalendar 格式。

GET/PUT /api/v1/catalog/admin/schools/{school_id}/terms/{term_id}/timetable 要求 catalog 管理能力及学校维护范围。配置保存第一周周一日期、IANA 时区与各节次起止时间，节次和时间递增，不允许重叠或跨午夜。

作息配置按学校和学期保存。创建使用 revision=0，更正使用当前修订；并发更正返回 conflict，紧接成功写入的相同旧修订请求返回原结果。配置不存在时返回 not_found。写入、审计与 outbox 同事务提交。
