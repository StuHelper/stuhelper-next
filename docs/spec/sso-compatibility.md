# SSO 数据与消费者兼容

## 范围与适用情况

为官方 Casdoor 镜像迁移定义数据、身份、会话和权限的目标行为，涵盖 AI、Store、旧主站及清点出的所有接入系统。官方镜像形态已确认；具体切换窗口和旧会话不兼容处理仍需依据演练决定。当前未完成生产迁移或真实账号矩阵。

## 身份与授权不变量

- issuer 保持 `https://sso.stuhelper.com`，包括协议、路径和尾斜杠语义；每个应用保留原 client ID 和准确回调 URI。
- 对已有账号，subject 必须与切换前字节一致。新业务内部使用 `(issuer, sub)` 唯一绑定稳定 `user_id`；不得按 email、手机号或显示名自动重新关联。
- 公钥、kid 与历史签名验证保持兼容；正常轮换需重叠发布新旧 key 至存量 token 过期。验证签名、issuer、audience、expiry、state、nonce 和 PKCE 的责任不能因升级省略。
- 不更改 AI 的订单/额度/余额归属、Store 的订单和账户绑定；这些数据不是 SSO 迁移的写入目标。
- 身份禁用、删除、组织范围及管理员降权必须按各消费方既有契约生效。普通 roles claim 不能替代服务端管理员权威。
- SSO 暂时不可用与主体非法应区分：依赖故障不能被伪装成身份更换、自动新建账号或自动解绑。

## 数据保留

保留完整数据库及关联持久化资源，不只导出用户名再建账号：

| 数据 | 必须保持/验证 |
| --- | --- |
| 用户 | UUID、组织、用户名、密码哈希与算法参数、资料、禁用/删除状态、管理员状态 |
| 登录因子 | MFA、WebAuthn/passkey、恢复材料、第三方身份绑定及其解密依赖 |
| 组织与应用 | owner/name、client ID、现有 secret、准确 redirect URI、scope、token 配置 |
| 密钥与证书 | 签名私钥及证书、JWKS kid、公钥集合、现有 token 可验证性 |
| 上游 providers | 邮件、短信、社交/学校身份提供方配置、凭据引用与登录规则 |
| 会话与令牌 | DB/Redis/session 文件及 cookie 配置、refresh token 家族、授权与撤销事实 |
| 自定义与审计 | 角色、权限、审计、扩展字段、主题、附件/头像及对象存储关联 |
| 外部系统映射 | AI / Store / 旧站已有用户绑定、历史订单/余额归属不随迁移变更 |

数据库备份、配置、加密密钥和对象存储需要形成可恢复的一致集合。比较表数量/行数之外，按稳定主键核对身份集合和受保护字段的受控摘要；对敏感值用运行时密钥 HMAC，不能发布可枚举手机号/邮箱的普通哈希。密钥和原始行不进入 CI 输出。官方自动维护的内部 API 策略投影需单独依据准确版本来源核对，不能把它与自定义用户权限一起跳过。

用户数据保留和无感保留每个旧会话是两项验收：若某类旧会话确实不兼容，必须在切换前记录影响并决定重新登录策略；不得默默换 subject、重建账号或声称完全无感。

## 验收场景

对旧版本和候选运行同一套测试，并记录准确镜像、客户端版本、非敏感结果与执行时间：

| 场景 | 必需结果 |
| --- | --- |
| 已有普通账号从 AI/Store 登录 | 回到原业务 user ID；订单/额度/资料归属保持，未创建重复账号 |
| 已登录 SSO 后跨应用登录 | 无须重新提供账号凭据（若既有策略本就要求重新认证，保留明确策略） |
| 管理员与普通账号 | 管理员可用、普通账号不可越权；组织范围不扩大 |
| subject / iss / aud 不符 | 拒绝，不自动修复或重绑 |
| state、nonce 错误和 code 重放 | 拒绝；合法一次性 callback 成功 |
| refresh 与旧会话 | 合法续期仍属原用户；轮换失败不会丢失有效本地会话或换号 |
| logout 与再次登录 | 本地注销和全局注销语义分别验证，不假设 OIDC 登录自动实现全局单点退出 |
| 降权、禁用、删除 | 按既有即时/有效期策略拒绝受保护操作，无旧权限复活 |
| 密码、MFA、passkey、已配置上游 provider | 每个实际启用方式有验收证据；未执行项明确 pending |
| SSO 网络故障 / JWKS 更新 | 已知 key 合法 token 与需实时校验操作按契约处理；未知 key 不放行 |
| 浏览器 v4 页面 | authorize、signup、forgot-password、同意页、主题、资源路径和回调正确 |

凭据、token、cookie、原始 userinfo、数据库行、真实用户截图不得出现在公共仓库和 Actions artifact。不涉及 Docker build 或 BJ1 Registry 的合成测试可在标准托管 runner 执行；镜像相关任务遵循[runner 规格](ci-runners.md)，生产数据演练仅在受控环境执行。真实登录验证的成功回执只包含测试项和匿名结果。

## 完成判据与失败语义

必须完成全量消费者清点，每个必需场景真实通过，实际恢复数据库，核对运行镜像与锁定候选、原账号映射和数据不变量。pending、skipped 或仅 discovery 成功均不足以宣告迁移完成。

未执行或失败的项目按具体原因记录；不能通过换 subject、重建用户、放宽 claims/权限校验或修改检查结果消除失败。发现未知的用户数据变化须中止后续切换。候选首次访问生产库后的恢复边界见[SSO 设计](../design/independent-sso.md)。

## 关联与待确认事项

消费者实际配置、旧会话兼容、外部 provider 方法清单、维护窗口及差异修复由[SSO 迁移工作](../development/sso-migration.md)逐项闭环。用户资料、原始 token/账号映射和生产快照不进入公共仓库或 Actions artifacts。
