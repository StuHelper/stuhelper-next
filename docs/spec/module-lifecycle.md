# 模块生命周期

## 范围与适用情况

定义多仓库模块与外部扩展的目标行为，供服务端、客户端和运维使用。[模块清单](https://github.com/StuHelper/stuhelper-next/blob/develop/architecture/modules.yaml)记录模块归属。首期框架通过配置与重启启停模块，当前没有在线管理开关；运行机制见[框架实现设计](../design/framework-runtime.md)。

## 模块与依赖

能力（capability）表示模块提供的功能或操作。schema 表示数据库结构，outbox 保存等待发送的业务事件。统一术语见[术语表](terminology.md)，消息字段与投递约定见[模块协议](module-protocol.md)。

模块在自己的仓库维护接口与版本，使用方固定版本并进行兼容检查。模块声明自身版本、必需与可选依赖、提供的 API、能力和事件、schema 支持范围、健康与关闭方式。必需依赖必须启用且版本兼容，必需依赖图保持无环。可选依赖存在时检查接口版本，能力声明自己需要哪些可选依赖。可选依赖缺失只影响对应能力，通过公开接口或事件协作。

模块只写自身数据。业务变更、相关审计和 outbox 同事务提交；事件至少一次投递，消费者按事件标识去重并防止旧 revision 覆盖新状态。跨模块原子要求需显式设计协调机制，不假设共享进程自动保证一致性。

## 可观察生命周期

| 操作 | 条件 | 预期结果 |
| --- | --- | --- |
| 启用 | 必需依赖、schema 和配置通过检查 | 注册公开入口与 worker，报告就绪 |
| 缺少必需依赖 | 配置缺少必需模块或版本冲突 | 启动失败并指出依赖原因 |
| 远程服务中断 | 已安装的服务暂时不可达 | 组合启动，相关能力暂停，后台探测恢复 |
| 可选依赖中断 | 能力声明依赖该服务 | 该能力暂停，其余能力继续运行 |
| 不安装 community | 其他模块依赖检查通过 | 课程、评价、评价内回复/投票/收藏及资料仍可用；社交动态入口不可用 |
| 关闭 resources | 停止新任务，保留既有事实 | 停止新上传/下载，保留数据与审计；已签发下载 URL 最长 5 分钟有效 |
| 关闭被依赖模块 | 仍有启用的必需依赖方 | 拒绝并给出依赖清单，或执行经确认的连带关闭计划 |
| 更新 | 兼容范围和迁移完成 | 切换到指定模块版本，不由开关触发 schema 回退 |
| 卸载 | 已停入口/worker，任务已排空或保留 | 模块不再提供服务；数据删除另行决定 |

缺少 billing 时，免费资料仍可提供，收费相关入口不可用。资格服务不可用时，需要其结论的操作返回暂不可用，不能自动放宽资格。模块恢复后重新检查就绪与能力，既有数据和权益保留。

## 声明与实际运行

模块清单区分设计中的模块与已有实现。已实现模块声明接口主版本、能力、依赖和关键性，共享工程工具从该声明生成模块 JSON。运行时直接读取这份生成数据，提供方检查生成一致性，工作区检查实际组合与声明一致。

动作资格由业务模块 Service 汇总当前配置和所需事实，platform 的公共求值接口处理事实输入。事实提供方记入业务模块依赖，静态能力依赖只表达始终需要的模块。详细顺序见[动作资格配置](action-eligibility.md)。

## 客户端与扩展

客户端读取服务端能力列表和最低支持版本，隐藏未启用或不支持的功能，深链接也须返回明确状态。后端仍执行全部权限检查，不能以客户端隐藏入口代替拒绝访问。

业务模块按固定版本静态装配，也可按实际需要注册独立服务。仓库是否私有不决定注册方式。启动时核对能力，运行中支持停止新操作、排空任务和关闭。外部扩展运行在独立进程或通过 webhook 接入，需有权限范围（scope）、超时、限流、签名、重放保护和审计。首期没有上传代码到主进程热加载的入口，也不提供 Go `.so` 插件 ABI。

API 采用版本和弃用期。事件封套、顺序键、去重、幂等保存期限与补偿记录由[模块协议](module-protocol.md)定义，数据生命周期由[保留规格](data-retention.md)定义。可选未知字段可忽略，未知权限和必需能力返回明确错误。

## 验收场景

| 场景 | 初始条件与动作 | 预期结果 |
| --- | --- | --- |
| MOD-01 | community 未安装，浏览课程与评价正文 | 评价与其互动正常可用，社交动态入口关闭 |
| MOD-02 | reviews 启用，尝试关闭必需 catalog | 拒绝并说明依赖，不丢失评价数据 |
| MOD-03 | 重复投递同一发布事件，随后投递旧 revision | 不生成重复内容或让投影倒退 |
| MOD-04 | resources 关闭后访问旧深链接 | 明确报告功能不可用，不自动清库 |
| MOD-05 | 未授权扩展请求受保护能力 | 拒绝并记录脱敏审计，不绕过中央权限或审核 |
| MOD-06 | 可选资格服务缺失，模块同时提供浏览与发布能力 | 浏览保持可用，依赖资格的发布暂停 |
| MOD-07 | 远程服务返回 503 或迟迟没有响应 | 在启动探测预算内进入降级状态，服务恢复后能力恢复 |
| MOD-08 | 高频请求与服务凭据轮换同时发生 | 请求只读取缓存，后台探测使用新凭据恢复 |
| MOD-09 | 非关键业务服务故障，platform 正常 | 进程继续就绪，能力和管理健康状态如实显示故障 |

框架关闭预算为 15 秒，持久化任务通过恢复记录继续执行。事件兼容与签名 URL 有效期遵循[模块协议](module-protocol.md)。仓库划分见[多仓库设计](../design/module-repositories.md)。机制见[平台架构](../design/platform-architecture.md)，计划见[重写路线](../development/rewrite-roadmap.md)。
