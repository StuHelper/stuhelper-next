# 模块生命周期

## 范围与适用情况

定义 Next 内置模块和外部扩展的目标行为，供服务端、客户端和运维使用。当前仅有[设计依赖清单](https://github.com/StuHelper/stuhelper-next/blob/develop/architecture/modules.json)，没有运行时模块加载器。

## 模块与依赖

模块声明自身版本、必需/可选依赖、提供的 API、capability 和事件、schema 支持范围、健康与关闭方式。必需依赖必须存在且版本兼容，整体不能成环；可选依赖通过公开接口或事件适配，不导入对方私有实现。

模块只写自身数据。业务变更、相关审计和 outbox 同事务提交；事件至少一次投递，消费者按事件标识去重并防止旧 revision 覆盖新状态。跨模块原子要求需显式设计协调机制，不假设共享进程自动保证一致性。

## 可观察生命周期

| 操作 | 条件 | 预期结果 |
| --- | --- | --- |
| 启用 | 必需依赖、schema 和配置通过检查 | 注册公开入口与 worker，报告就绪 |
| 缺少必需依赖 | 配置不完整或版本冲突 | 启动失败并指出依赖原因，不悄悄降级 |
| 不安装 social | 其他模块依赖检查通过 | 课程、评价正文、资料仍可用；互动入口不可用 |
| 关闭 resources | 停止新任务，保留既有事实 | 禁止新上传/下载，保留数据与审计；已签发 URL 的失效上界须明确 |
| 关闭被依赖模块 | 仍有启用的必需依赖方 | 拒绝并给出依赖清单，或执行经确认的连带关闭计划 |
| 更新 | 兼容范围和迁移完成 | 切换到指定模块版本，不由开关触发 schema 回退 |
| 卸载 | 已停入口/worker，任务已排空或保留 | 模块不再提供服务；数据删除另行决定 |

## 客户端与扩展

客户端读取服务端 capability 和最低支持版本，隐藏未启用或不支持的功能，深链接也须返回明确状态。后端仍执行全部权限检查，不能以客户端隐藏入口代替拒绝访问。

首期采用编译时注册、启动时启用；外部扩展运行在独立进程或通过 webhook 接入，需有 scope、超时、限流、签名、重放保护和审计。首期没有上传代码到主进程热加载的入口，也不提供 Go `.so` 插件 ABI。

API 采用版本和弃用期，事件带有 `id/type/version/occurred_at/aggregate_id/revision/trace_id`。可选未知字段可忽略，未知权限和必需能力必须明确拒绝。敏感身份数据不进入通用事件。

## 验收场景

| 场景 | 初始条件与动作 | 预期结果 |
| --- | --- | --- |
| MOD-01 | social 未安装，浏览课程与评价正文 | 正常阅读，社交入口消失且直连互动 API 被拒绝 |
| MOD-02 | reviews 启用，尝试关闭必需 catalog | 拒绝并说明依赖，不丢失评价数据 |
| MOD-03 | 重复投递同一发布事件，随后投递旧 revision | 不生成重复内容或让投影倒退 |
| MOD-04 | resources 关闭后访问旧深链接 | 明确报告功能不可用，不自动清库 |
| MOD-05 | 未授权扩展请求受保护能力 | 拒绝并记录脱敏审计，不绕过中央权限或审核 |

关闭时任务排空超时、事件兼容期和签名 URL 有效期在具体实现前确定。机制见[平台架构](../design/platform-architecture.md)，计划见[重写路线](../development/rewrite-roadmap.md)。
