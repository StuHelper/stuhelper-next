# 模块通信与一致性

## 事件封套

跨模块事件采用 CloudEvents 1.0 结构。业务写入和 outbox 在所属模块的同一数据库事务提交。生产者通过获准通道发送，消费者使用自己的 inbox 去重和处理记录。

| 字段 | 约定 |
| --- | --- |
| `specversion` | CloudEvents 协议版本，当前为 `1.0` |
| `id`、`source` | 事件 ID 与模块来源共同唯一；同一事件重试沿用原值 |
| `type` | 含模块、动作及业务事件主版本的稳定类型 |
| `time` | 事件发生的 UTC 时间 |
| `datacontenttype` | 当前为 `application/json` |
| `subject` | 业务对象类型与稳定 ID |
| `traceparent` | 调用追踪上下文，存在追踪时填写 |
| `schoolid` | 学校范围事件填写，平台范围事件省略 |
| `data.revision` | 业务对象修订号，单调递增 |
| `data` | 本事件公开接口定义的最小业务字段 |

按 `(source, subject)` 分区确保同一对象按序发送。消费者独立验证范围、来源和修订号。重复事件返回已处理结果，旧修订事件忽略；依赖增量顺序的投影遇到缺口时暂停应用增量并重新取得完整状态。完整替换事件可按其契约接受较新修订。

普通事件只传递结论、状态和稳定标识。原始身份材料、学校凭据和支付载荷保存在所属服务。

## 事件投递

生产者在业务事务中写入 outbox 并调用 pg_notify，事务提交后唤醒 relay，回滚不发送通知。relay 通过 LISTEN 接收唤醒，再读取未发送事件。启动和重连立即补读，空闲时每 60 秒兜底扫描；监听连接不可用时仍执行补读。

同一来源的多个 relay 通过数据库锁串行投递，按主题 subject 保序。主题失败时暂停该主题后续事件，其他主题继续处理。读取 outbox 时在排序和 LIMIT 前排除退避或人工处理中的主题，避免失败主题占满首批。

排除集合最多 1000 项，超限时优先保留最早恢复的主题，人工主题排后并记录容量告警。未进入集合的受阻主题仍在本地拒绝提前消费。单次消费限时 10 秒，单轮补读限时 2 分钟。

消费者将 inbox 去重记录、对象修订和业务结果同事务保存，重复事件返回原处理结果，旧修订不覆盖新状态。消费成功后生产者才确认 outbox；消费成功但确认失败时，重放仍只产生一次业务效果。

一个通知事件包含完整收件人集合，一次调用消费者。接收人去重后，全部通知、偏好抑制结果、inbox 与修订在同一事务写入，任一写入失败全部回滚。旧修订和互动偏好抑制分别记录原因，不能部分确认来源事件。

## 幂等请求

可重试写接口使用 `Idempotency-Key`，长度为 1—128 个可打印 ASCII 字符。作用域包含操作者、模块、动作和业务对象。相同键与相同请求摘要返回同一操作结果；相同键对应不同请求返回 409。

请求摘要根据接口定义的规范化字段计算。接收、执行中、完成和失败状态持久化。执行中请求返回 202 和操作查询地址；完成响应保留 24 小时。客户端为新的用户操作生成新键，网络重试沿用旧键。

账务、权益和奖励还使用订单、提供方流水、授予对象与来源事件的数据库唯一约束。请求响应缓存到期后，这些业务唯一性继续有效。外部回调以提供方和外部事件标识去重。

## 跨模块步骤

跨模块写流程记录操作 ID、步骤、幂等键、请求摘要、执行状态、外部标识、重试时间和补偿状态。超时进入结果待确认状态，先查询实际结果，再选择重试或补偿。

补偿使用独立幂等操作。允许撤销的权益、预占和临时文件按已记录的来源处理；已发生的外部效果通过退款或后续处置记录表达。持续失败的流程进入人工处理列表，保留已完成步骤。

outbox 发送从 5 秒开始指数退避，单次等待最长 1 小时，累计重试窗口为 24 小时。首次失败满 24 小时后持久标记为人工处理，保留事件且不自动丢弃。管理员可以查看脱敏错误码并按原事件 ID 显式重试。消费者处理与 inbox 确认在本地事务中提交。

## 文件签名

下载 URL 默认有效 5 分钟，应用允许的最大有效期也是 5 分钟。签发前重新检查文件状态和当前访问权，签名绑定对象版本及下载操作。权限撤回和文件下架立即停止签发新 URL，已有 URL 对新请求的最长影响为剩余有效期。已经传出的文件与正在进行的下载按传输状态处理。

上传 URL 有效 15 分钟，绑定上传会话、对象路径、大小和类型。上传会话与未引用临时对象保留 24 小时。完成操作校验实际对象并建立业务引用；取消、重试和过期按会话 ID 幂等执行。

## 数据库边界

每个模块创建自己的 schema 和数据库访问身份。运行账号只获得自身数据所需权限，迁移账号单独管理 DDL。跨模块读写经公开接口执行，组合进程保留各模块的独立连接与凭据。

导入检查限制跨模块实现包依赖，Handler、Service、Repository 按职责组织。数据库集成测试使用模块运行身份验证越界访问被拒绝。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| MP-01 | 同一事件重复投递时，消费者只产生一次业务效果 |
| MP-02 | 旧 revision 或增量缺口分别被忽略或进入状态重建 |
| MP-03 | 同一幂等键换请求内容时返回 409，重复原请求返回原操作 |
| MP-04 | 外部请求超时后先查询真实结果，避免重复扣款或重复授予 |
| MP-05 | 文件下架后停止签发，旧下载 URL 在有效期上界内失效 |
| MP-06 | 模块运行身份访问其他 schema 时被数据库拒绝 |
| MP-07 | 提交后唤醒，回滚不投递，启动、重连与 60 秒扫描补读积压 |
| MP-08 | 同主题保序，跳过退避主题，24 小时后转人工，原事件重试不重复生效 |
| MP-09 | 多收件人去重与偏好处理同事务保存，失败全部回滚，旧修订不覆盖新结果 |

封套字段参考 [CloudEvents 1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md)。业务事件、补偿动作和数据库实现随对应模块加入，验收时使用实际持久化与故障重试测试。
