# 内容运营与审核

## 范围

后台内容运营已确认纳入重构，包括内容审核、举报处理、隐藏与恢复、作者修改/删除申请和处理反馈。本文定义管理员和用户的目标体验。发布前后的审核顺序与具体角色分工仍待确认。

## 工作台与处理流程

管理员在自己的管理范围内查看待处理内容、举报及作者申请，按内容类型、状态、学校和时间筛选，进入详情查看内容及对应申请。一个内容的多项处理记录可以集中查看，避免管理员不知道已有处理结果。

| 事项 | 已确认业务能力 |
| --- | --- |
| 内容审核 | 查看待审内容，给出处理决定并说明结果 |
| 举报 | 查看举报对象和原因，判断是否成立并处理，向举报者反馈结果 |
| 内容隐藏与恢复 | 管理员隐藏不适宜展示的内容，符合恢复条件时恢复展示 |
| 评价修改申请 | 查看作者提出的修改，决定是否采用并向作者反馈 |
| 评价删除申请 | 查看申请与内容，决定是否删除并向作者反馈 |
| 资料下架申请 | 查看资料、申请原因及已有购买等相关情况，按资料规则处理 |

课程评价和教师评价发布后，作者不能直接编辑或删除，规则见[评价规格](academic-content.md)。申请提交不等于管理员已经批准，也不立即改变已发布内容。资料的下架处理与作品授权存续分别判断，见[资料规格](resource-sharing.md)。

## 状态与反馈

用户能够查看本人申请处于等待处理、已处理或未获通过等状态，查看管理员反馈。处理通知进入[通知中心](notifications.md)，并可返回对应内容或申请。

隐藏、恢复、删除和资料下架是不同业务结果。后台应说明将发生的变化，不能把隐藏内容表述成永久删除，也不能在操作尚未完成时显示处理成功。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| CM-01：作者申请修改已发布评价 | 原内容不因申请提交自动改变，管理员可查看并处理 |
| CM-02：管理员处理举报 | 能查看对象和理由，决定与反馈关联到原举报 |
| CM-03：内容被隐藏后符合恢复条件 | 管理员可恢复，并向相关用户反馈真实结果 |
| CM-04：作者申请下架已被购买的资料 | 能查看相关购买情况，按资料交付与退款规则处理 |
| CM-05：管理员超出本人管理范围进入内容 | 不能因为拥有某个后台角色就处理范围外内容 |

## 待确认事项

不同内容先审后发还是先发后审、具体违规分类、批量处理范围、敏感词规则、管理员是否可以主动修改作者原文、作者申诉或复核机制、删除后是否可恢复以及审核岗位划分尚待确认。旧系统中的处罚和审计实现需按后续确认的规则另行评估。
