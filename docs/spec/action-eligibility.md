# 动作资格配置

## 范围

所有业务动作的用户资格均可配置。各业务规格中已经确认的条件作为初始默认值，实际操作采用当前生效规则。管理员可以快捷调整某个动作，例如为资料上传追加独立实名要求。

资格配置说明谁满足动作的身份条件。内容归属、管理员管理范围、资料访问权、支付价格和可用余额等业务规则仍由相应业务检查，不能因为满足身份条件而跳过。

## 配置与管理范围

平台管理员维护每个动作的全站默认条件。获得该项配置权限的学校或业务管理员，可以在自己的范围内建立覆盖规则，允许收紧或放宽默认条件。

界面按动作显示登录、校园资格、手机号、独立实名及该动作支持的其他条件。多个必需条件需要同时满足，允许替代的资格明确说明可任选其一。管理页面显示作用范围、规则来源和最终生效条件，用户在操作入口看到自己尚未满足的条件及完成入口。

没有范围覆盖时采用全站默认。范围覆盖只作用于管理员获准的对象，不能改变其他学校或业务的条件。出现无法确定唯一生效规则的配置时，提示配置冲突，由有权管理员处理。

## 内容准入

当前只服务北京航空航天大学。内容准入要求有效校园资格或有效教师认证，有效校园资格包含普通认证、已认证校友和未过期的临时新生。内容准入决定用户能否进入内容区，动作资格决定进入后能否执行具体操作。进入课程页面之后，发布评价仍按可信选课记录判断，管理操作仍需要独立管理权限。

客户端区分未登录、未认证、认证处理中、认证通过、认证失效和资格读取失败，并在认证通过后回到原页面。读取失败不代表认证失效，内容保持关闭并提供重试。

服务端读接口、搜索和统计按同一条件执行授权。客户端的准入页面只改善体验，不能替代服务端检查。认证失效的用户仍可查看和管理本人记录，公共内容区保持关闭。

本人记录的名称查询仅返回必要名称，不开放公共详情。评价草稿由服务端记录已通过内容准入验证的关联，只有这些关联可以查询名称。未验证的草稿仍可保存，恢复资格后再验证；自行填写关联 ID 不构成名称读取授权。

本人投诉回执仅在提交投诉时已经通过内容准入的情况下保存并显示目标资料标题。其他投诉回执只显示资料 ID 和处理状态。提交后取得资格不补发此前未保存的标题，回执不返回资料正文、文件或预览。

| 场景 | 预期结果 |
| --- | --- |
| AE-ACCESS-01：未登录访问内容页 | 显示登录入口，不发送业务请求 |
| AE-ACCESS-02：账号状态读取失败 | 内容保持关闭，只提供重新检查 |
| AE-ACCESS-03：未认证、处理中或已失效 | 分别说明状态，入口带上原页面地址 |
| AE-ACCESS-04：认证通过 | 进入内容；发布等操作仍按各自资格判断 |
| AE-ACCESS-05：认证失效后打开我的评价或我的课程 | 可查看和管理本人记录，打开课程详情仍显示准入提示 |
| AE-ACCESS-06：有效教师认证、无校园资格 | 通过内容准入 |
| AE-ACCESS-07：未通过准入的用户直接调用内容读接口 | 服务端拒绝，不返回预览或统计 |

## 配置操作

所有资格条件按动作和授权范围配置。平台管理员分配资格配置权限，学校或业务管理员修改本人范围的覆盖规则。保存前展示变更后的最终条件、受影响范围和规则版本。冲突配置返回明确错误，当前有效版本继续执行。配置变更记录操作者、作用范围、版本及结果。

资格配置独立于内容访问权、管理范围、金额、审核和数据归属。服务端分别检查这些业务条件。系统需要账号归属的动作使用已验证的操作者标识；具有资格配置权限的管理员可以调整校园资格、手机号、独立实名、选课等准入条件。

## 判定责任与依赖

platform 保存配置、规则版本和授权范围，提供只处理输入事实的公共求值接口。规则采用明确的条件组合，当前设计使用固定条件类型。业务模块的 Service 编排一次完整判断：

1. 读取当前动作和范围的有效规则。
2. 按规则需要，通过公开接口取得校园资格、手机号或本人选课记录等事实。
3. 将事实与规则交给公共求值接口，再检查资源归属、管理范围、审核和金额等业务条件。
4. 返回允许、资格不满足或所需服务暂不可用，记录必要的规则版本和审计。

校园资格和独立实名由 verification 提供，手机号由 identity 提供，可信选课记录由 catalog 提供。campus-adapters 负责导入来源，评价提交使用 catalog 已保存的事实。

业务模块在依赖清单中声明所使用的事实提供方。规则未启用的条件无须查询对应事实。启用条件所需的服务不可用时，操作返回暂不可用。platform 的公共求值接口保持无外部服务依赖。

静态 `capability_requires` 表达某项功能始终需要的模块，例如收费交易需要 billing。按学校、动作和当前规则变化的资格条件由请求中的 Service 判断。能力列表说明功能可用性，当前用户能否操作还取决于这次资格与业务判断。

## 生效与既有记录

配置更新在本实例立即生效，其他实例最多延迟 5 秒。既有内容、认证、积分与 Ivory、单独授权和已购权益保留，不因资格条件调整自动删除或退款。

例如上传新增实名要求后，未实名用户不能继续提交新资料或新版本，已经发布的资料保留。下载条件收紧后，尚未满足新条件的用户暂停后续下载，原购买权益保留，满足条件后无须重新购买。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| AE-01：为资料上传追加独立实名条件 | 后续提交检查实名，未实名用户能看到需要完成的条件 |
| AE-02：学校管理员配置本人学校的覆盖规则 | 只影响该学校范围，其他范围继续使用原规则 |
| AE-03：有配置权限的管理员放宽某范围的资格 | 该范围按新条件检查，管理权限和资料访问权仍单独检查 |
| AE-04：已购用户暂时不符合新的下载条件 | 暂停后续下载，保留已购权益，不自动扣费或退款 |
| AE-05：用户满足资格但没有资料访问权 | 仍需取得访问权，不能仅凭资格下载受限资料 |

全部动作资格可配置，支持全站默认与授权学校范围的覆盖。权限检查使用最长 5 秒的缓存，本实例修改后立即失效，其他实例最迟 5 秒采用新规则。缓存过期且数据库不可用时拒绝授权。

收藏由独立 favorites 模块拥有，每条收藏只属于一个收藏夹。移动后从原夹移除。删除收藏夹时保留收藏并移入默认收藏夹，默认收藏夹可以改名但不能删除。管理本人已有收藏夹和收藏不要求重新通过内容准入，新增收藏仍检查当前准入和目标状态。

同一用户的收藏夹名称去掉首尾空格后不得重复，默认收藏夹改名也适用。名称比较区分大小写，使用稳定收藏夹 ID 关联记录。

资格默认值、数据库配置和修改服务由 platform 统一提供。content.enter 独立于评价 read_full，目录与举报不依赖 reviews 的类型。管理员通过当前学校的 platform.eligibility.manage 权限读取和修改规则，写入要求预期版本及幂等键。

platform 使用自己的 PostgreSQL schema 和独立运行身份保存配置、安装历史、幂等响应及独立审计表。修改原子保存规则、审计和响应，原请求重试返回原结果，同键不同内容或旧修订被拒绝。

审计保留 12 个月，幂等响应保留 24 小时。后台每次各清理最多 100 条，操作限时 5 秒。历史记录数量不阻止配置修改。安装历史无法确认时按关闭处理。
