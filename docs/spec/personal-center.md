# 个人中心

## 范围

个人中心是用户管理本人信息、认证、账号绑定和内容的统一入口。以下业务范围已经确认，界面布局和未决细节仍待设计。

## 入口与行为

| 区域 | 用户可以做什么 |
| --- | --- |
| 个人资料 | 查看和编辑昵称、头像、简介等个人资料 |
| 认证情况 | 分别查看学生认证、实名认证和手机号绑定；进入认证或绑定流程 |
| 学生认证管理 | 查看学校与学习经历，提交撤销或删除申请，查看管理员处理结果 |
| QQ 绑定 | 分别查看三项状态，生成私聊验证码，发起 QQ 互联 OAuth，逐项解绑并查看入群提示 |
| 我的内容 | 查看本人评课、课程、教师和资料收藏、投票记录、评课草稿和上传资料，回到对应详情继续操作 |
| 我的课程 | 进入个人课程与课表，按学期查看 |
| 授权应用 | 查看第三方应用及用户授予的业务信息范围，取消应用授权 |
| 存储贡献 | 查看本人贡献容量、占用、期限和退出进度 |
| 积分与 Ivory | 分别查看积分和 Ivory 余额、明细、到期信息及退款进度，进入充值或购买积分流程 |

资料管理沿用[资料规格](resource-sharing.md)：允许编辑、更正和提出下架申请，不提供普通删除。认证操作沿用[认证规格](student-verification.md)，不能在个人中心另设直接撤销学生资格的快捷入口。

我的评价中，草稿可继续编辑。已发布的课程评价、导师评论和回复在首次发布五分钟内提供删除与撤回重编。撤回内容进入草稿箱并显示 24 小时到期时间，根评价删除或到期时整条讨论永久删除，具体行为见[评价规格](academic-content.md)。超过发布窗口的修改与删除由管理员处理。个人中心不提供匿名与署名切换申请。

学生资格、实名和手机号分别展示，不能用一个“已认证”标志代替所有状态。

## 公开个人主页

公开主页展示昵称、头像、简介及署名发表的公开内容。基础主页对游客可见。学校、认证徽章、学院、署名评价和资料默认公开，年级默认不公开。学院、年级、署名评价、资料、学校和认证徽章都可由本人关闭，关联内容仍按各自权限显示。匿名内容不关联到公开主页。真实姓名、证件信息、手机号、QQ、账户余额和退款记录不公开。

## 登录、设备与绑定

注册、登录与找回由独立 SSO 提供。个人中心支持退出当前设备和退出全部设备，界面说明撤销的是本应用会话。共享 SSO 与其他应用会话按各自规则管理。

手机号支持绑定、换绑和解绑，同一手机号只关联一个平台账号。QQ 绑定按 OneBot、QQ 互联、官方机器人三项独立验证和解绑，三项全部完成才提供整体绑定事实。发生归属冲突时走账号找回或管理员核查，不能覆盖另一个账号的绑定。解绑后，相关操作按当前资格配置判断。

## 业务账号注销

用户提交注销申请后进入 7 天冷静期，期间登录可撤销申请。冷静期结束后由管理员处理。未完成的退款与余额处置完成后，注销 StuHelper 业务账号，撤销本应用会话和业务授权。公开内容匿名化保留，处理过程保留必要记录。

注销 StuHelper 业务账号不删除共享 SSO 账号，也不删除 AI、Store 等其他应用的账号或业务记录。页面在提交申请前清楚说明处理范围。

完成注销后，同一个 SSO 身份不能自动重建或进入本应用业务账号。如需恢复，交由管理员处理。旧内容和资产不因再次登录恢复关联。注销无法核实资产状态时不得完成，账务模块提供资产核对与结清能力。

注销申请明确告知并要求用户确认：正式注销时清零长期积分、限时积分和待抵扣记录，不兑换现金或 Ivory。冷静期内撤销申请不改变积分。资产核对必须确认 Ivory 余额为零、退款完成且没有结果未明的支付，再原子冻结后续账务写入并清零积分。

注销同时通过 qq-binding 删除三项身份、验证码与绑定状态，并阻止后续绑定写入。

公开资料保留原作者、来源、许可证和正文，注销仅移除上传账号的公开关联。公开评价移除账号署名、个人主页关联和认证标签，保留评价正文与讨论结构。

## profiles 模块边界

昵称最多 20 个 Unicode 码点，个人简介最多 120 个 Unicode 码点，前后端按相同方式计数。首次登录依次使用合规的 SSO 显示名和用户名，都不合规时由用户填写。不修改 SSO 用户名。

认证情况只展示服务端生成的脱敏姓名（末字）和证件号（首尾位），星号数量等于被遮住的 Unicode 码点数，接口不下发完整身份信息。已实名记录必须有可核验的脱敏值。姓名不足 2 个 Unicode 码点或证件号不足 3 个 Unicode 码点按不合规输入拒绝。

profiles 拥有昵称、头像引用、简介、公开展示偏好和业务账号状态。身份登录由 identity 提供，校园资格由 verification 提供。头像通过 media 的上传与引用接口管理。修改资料使用本人账号和修订号，冲突时返回当前版本供用户选择。

公开主页只查询可公开字段和仍可见的署名内容。匿名内容、账号绑定、认证材料与账务明细通过各自服务的授权接口访问。注销流程记录资产处置、会话撤销、授权撤回与资料处理进度，重复请求沿用同一操作。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| PC-01：有学生资格但未独立实名 | 分别展示真实状态，发布评课按已确认门槛判断 |
| PC-02：从我的草稿返回编辑 | 回到本人未完成内容，可以继续编辑 |
| PC-03：从我的资料管理上传内容 | 可编辑、更正或申请下架，不出现普通删除入口 |
| PC-04：取消第三方应用授权 | 应用授权状态更新，不等同于注销账号或撤销学生资格 |
| PC-05：用户首次打开公开主页 | 学校和认证徽章默认公开，可由本人调整，匿名内容不关联 |
| PC-06：绑定已属于其他账号的手机号或 QQ | 提示找回或人工核查，不覆盖原绑定 |
| PC-07：管理员批准已完成资产处置的注销申请 | 注销本应用业务账号并匿名化公开内容，共享 SSO 与其他应用保留 |

| PC-09：冷静期内登录并撤销注销申请 | 申请撤销，账号与资产不受撤销申请影响 |
| PC-10：SSO 显示名和用户名都不合规 | 登录成功并要求用户填写昵称 |
| PC-11：查看本人实名状态 | 只返回脱敏字段 |
| PC-08：本人修改公开昵称 | 使用当前修订与幂等键，重复提交仅修改一次，同键不同内容与旧修订拒绝，其他账号资料相互隔离 |

## 配置与后续事项

草稿采用评价规格已确认的多份保存、跨端同步与冲突选择规则。个人中心采用相应模块已经确认的规则，具体布局在界面设计中确定。

注销内容步骤逐模块幂等执行：删除本人收藏、收藏夹和相关幂等响应，投票匿名保留并继续计入统计。失败保存进度并允许重试，已完成模块重复执行不会恢复账号关联或收藏。

只有持久安装记录明确证明模块从未安装时才跳过，并在注销结果记录模块名称。曾经安装但暂时关闭的模块必须等待恢复。记录缺失、损坏或无法确认安装历史时同样等待，不依据本次启用清单推断。

注销失败采用人工恢复：管理员在处理列表读取 blocker 和 completed_steps，确认依赖或资产问题处理完毕后，对原申请再次执行处理。服务端每次核验当前管理权限并沿原步骤继续。自动处理任务尚未启用，运行维护人负责跟进未完成申请。
