# 学生认证与实名认证

## 范围与状态

本文定义学生认证和可选实名认证的流程。已确认规则见下文，学校方法清单和资格期限等问题在文末列出。两种认证与北航入口的关系见[学生资格与实名身份](../design/student-identity.md)。

## 已确认的认证体验

用户从个人中心独立进入学生认证，选择学校，再选择该校开放的方法，提交所需信息，查看验证或审核结果。学校账号、学校邮箱、实名信息校验、材料审核是认证方法的候选类型，具体学校开放哪些方法需要逐校确定。

系统分别记录正式学生资格和临时新生资格，并保留本科、硕士、博士及跨校学习经历。例如用户新增硕士经历后，本科经历仍然保留。资格有效期和各业务对这些身份的适用规则仍需确认。

## 发布前置条件

| 行为 | 已确认条件 |
| --- | --- |
| 发起学生认证 | 登录；认证本身不强制绑定手机号 |
| 阅读完整评课 | 已认证学生；游客和未认证用户只看预览 |
| 下载资料 | 普通用户须保持有效学生资格；受限资料另须有效访问权；管理员仅在本人管理范围内例外 |
| 发布课程或教师评价 | 登录、学生认证通过、已绑定手机号；不额外要求独立实名认证，也不要求系统提供对应选课证明 |
| 发布其他内容 | 保留发布前绑定手机号的通用要求；各类内容是否另需学生资格由其规格说明 |
| 单独完成实名认证 | 用户可以主动进入；按已经支持的核验方式完成，不是所有用户必做的步骤 |

实名认证状态用于身份核验。课程与教师评价默认匿名，主动署名使用平台昵称和头像。个人主页的公开字段另行确定，具体评价展示规则见[评价规格](academic-content.md)。

## 北航实名信息校验

北航学生认证保留“实名信息校验”方法。用户提交学号、姓名和证件信息，使用北航学籍数据库信息核对；沿用原方式对相关信息与学生状态一致性的判断。全部条件满足后，同时完成北航学生认证和实名认证，用户不需要再额外提交一次实名认证。

北航学生从单独实名认证入口发起核验时，也优先使用北航学籍数据库信息比对。不能因为用户自称北航学生、只匹配到姓名或只完成其他学生认证方式就直接显示实名通过。

无相应记录、信息不一致和服务暂不可用均不能显示认证成功。服务不可用与信息不匹配应给出相应的可理解反馈；用户可查看该校其他已开放学生认证方式。其他方式完成学生认证，不自动补成“北航实名比对成功”。

## 认证撤销与删除

用户提交学生认证撤销或删除申请，管理员决定是否批准并反馈结果。申请处理期间，资格按原状态判断。管理员撤销和资格自然到期分别记录。

资格失效后的 QQ 群处理遵循[提醒、宽限期与管理员豁免规则](qq-group-services.md)。认证删除对历史学习经历、本人内容和其他已取得权益的具体影响仍待确认，不把“删除认证”解释成删除用户的全部内容。

## 后续实人认证

北航学籍数据库未覆盖的用户和其他学校用户，后续考虑使用腾讯云或阿里云实人认证。服务商、产品及采集流程以后确定。学生认证中的材料审核继续按学校认证规则处理。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| SV-01：未绑定手机号的登录用户进入学生认证 | 可以进行认证，不在入口强制绑定手机号 |
| SV-02：学生资格已通过、手机号已绑定，尚未独立实名，发布评课 | 身份条件满足，不额外要求独立实名 |
| SV-03：北航实名信息校验的全部条件满足 | 学生认证和实名认证同时显示通过，不重复要求实名 |
| SV-04：北航学生单独完成实名核验 | 优先使用学籍比对；通过后显示实名成功 |
| SV-05：无记录、不匹配或核验服务不可用 | 不显示成功，不伪称已经调用云实人认证服务 |
| SV-06：用户提交撤销申请 | 进入管理员处理流程，提交动作不直接撤销资格 |
| SV-07：用户新增研究生或另一学校经历 | 能表达新经历，原经历不被简单覆盖 |

## 待确认事项

逐校方法清单、临时新生适用范围、资格有效期与续期方式、删除认证的历史保留与权益影响，以及未来实人认证服务的选择仍需项目负责人决定。旧文档中“外校仅人工”与“按学校开放账号或邮箱”存在冲突，不自动继承其中一项。
