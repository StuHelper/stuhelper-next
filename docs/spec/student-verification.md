# 学生认证的公共对接说明

## 用户入口

个人中心分别展示学生资格、独立实名、手机号与 QQ 绑定状态。用户可以发起认证、查看结果，并申请撤销或删除学生认证，由管理员处理。两种认证的状态分别展示。

有效校园资格包括普通认证、已认证校友和未过期的临时新生。普通认证长期有效，只有限时凭证提示到期，群接纳范围及各业务动作条件由对应配置决定。一个账号可以保留多段学习经历。

## 模块协作

业务模块按[动作资格配置](action-eligibility.md)检查服务提供的资格结论。服务不可用时，需要该结论的操作返回暂不可用，不将未知结果视为通过或失败认证。

用户已有内容与权益按相应业务规则保留。认证服务不直接修改评价、资料、账户或群成员数据，而是提供授权范围内的状态变化，由各业务处理。

## 教师认证与公开属性

认证模块对外提供有效教师资格、账号到教师档案的可信映射，以及获准公开的属性。属性包含来源、修订、有效期与公开授权，业务模块不读取认证材料。学生真实姓名、性别和学院，以及教师真实姓名、性别和单位，均按字段授权提供。

教师认证首期由本人提交申请和材料。管理员可以要求补充材料，审核通过后建立账号与教师档案的可信绑定。自动核验后补，不从昵称或普通登录推断教师身份。

一个账号可以绑定多份经人工确认属于本人的教师档案。目录合并后按规范 ID 处理。同一有效教师档案只能属于一个账号，归属冲突由管理员处理。

教师资格不替代任课关系。评课模块通过 catalog 查询教师是否曾教授目标课程，再按课程评价规格决定是否要求实名。学校同步保持共用接入边界，课程和认证模块分别保存自己的业务数据。

## 私有规格

完整认证方法、材料处理、身份归属与核验规则维护在 [私有学生认证规格](https://github.com/StuHelper/stuhelper-verification/blob/develop/docs/spec/student-verification.md)。本页保留公共业务所需说明，不重复保存具体认证方案。

## 教师认证后端验收

| 场景 | 预期结果 |
| --- | --- |
| SV-TEACHER-01：教师申请、补充材料、审核及公开授权变化 | 独立教师资格和获准公开属性按当前状态返回 |
| SV-TEACHER-02：并发绑定同一教师档案 | 只允许一个账号取得有效绑定，资格与事件同事务保存 |
| SV-TEACHER-03：自审、依赖不可用、到期或撤销 | 明确拒绝或返回暂不可用，不产生有效认证兜底 |
| SV-TEACHER-04：认证数据迁移与运行身份检查 | 保留既有学生记录，运行身份不能越界或执行迁移 |
