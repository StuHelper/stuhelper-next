# 全站信息关联查询

## 范围与入口

“信息查询”是独立管理菜单，与群聊管理和娱乐功能分开。information-query 通过各业务模块的公开接口查询，只持久化查询审计，不保存身份原值或业务查询投影，不读取其他模块的数据库。

POST /api/v1/information-query/query 解析线索并返回分组记录，POST /api/v1/information-query/audit/query 分页查询审计。OpenAPI 版本为 0.2.0。请求使用当前登录会话，写请求校验 CSRF，请求 ID 与 admin 渠道由服务端生成。

## 线索归属与候选分组

| 线索 kind | 解析方与条件 |
| --- | --- |
| name | verification 按姓名及当前授权范围解析 |
| student_id | verification 按学号解析，必须指定学校 |
| qq | qq-binding 按 QQ 线索和当前授权范围解析 |
| account | 使用 issuer 与 subject 组成的完整账号键，直接形成候选 |

业务域只接收解析后的完整账号键。姓名、学号和 QQ 值不能直接替代账号。解析器先按操作者范围过滤，information-query 再检查候选范围及披露权限，不能靠关联线索扩大查询权限。

响应 groups 按候选分组，每组包含 candidate 和 items。候选保留 account、source、current、changed_at、scope 与掩码 label。同名对象分别展示，同一账号的不同来源或历史绑定也保持独立。

历史绑定使用 current=false，显示变更时间及来源，不作为当前归属。OneBot、QQ 互联与官方机器人身份分别核验，不能相互证明属于同一 QQ。account 直接查询的 changed_at 是请求时间，不表示绑定变更。

每页最多 100 条业务记录和 50 个候选。组合游标绑定请求人与查询条件，记录候选和业务记录位置。续页重新检查权限；候选事实变化返回暂不可用，调用方从首页重新查询。短页仍可能带 next_cursor，读取到游标为空才结束。

## 数据域与授权

| 数据域 | 当前接入 |
| --- | --- |
| verification | 身份、认证及学校范围内的历史凭据 |
| profiles | 公开资料与 QQ 绑定，分别使用 profiles:profile: 和 profiles:qq: 记录前缀并保留来源 |
| reviews | 账号关联的评价与讨论记录，匿名作者信息另行授权 |
| resources | 资料、授权、购买来源和会员覆盖记录 |
| groups | 入群申请、成员资格及群管理记录 |
| billing | 账务、资料订单与交付状态、会员期间及来源、退款记录与受独立权限保护的收款资料 |
| catalog | 指定学校内本人的选课记录 |

每个域先检查 `information-query.<domain>.read`，再由提供方独立检查业务能力和学校、群范围。普通成员和默认角色模板不自动获得这些能力。平台管理员及显式获授对应范围的管理员按当前授权查询。

profiles 与 QQ 绑定的学校范围依据 verification 当前凭据，群范围依据 groups 当前已加入的成员记录。verification 返回的身份记录保留来源学校范围，包括历史凭据。群管理权不自动授予财务或身份材料查看权。

姓名、学号、手机号与 QQ 默认掩码。完整身份、证件号码、认证原始材料和退款收款资料分别检查敏感类别权限，提供方仍执行自己的字段授权。未申请完整身份时返回掩码，其他未申请的敏感类别省略。

申请未授权域返回 403，不返回部分结果；已授权但未装配的域列入 unavailable_domains。解析器或已装配提供方发生故障时返回 503。没有候选返回空 groups，不能把依赖故障显示为没有记录。

查询能力与修改能力分别授予。查阅退款、积分或认证记录不授予付款、积分发放或认证修改权，相关操作进入所属模块的管理流程。catalog 不提供跨账号查询，解析到其他账号时返回暂不可用。

## 机器人入口

机器人信息查询默认关闭。启用后，私聊与群聊均依据请求人的当前权限返回字段，执行相同的掩码、敏感展开与审计检查。群聊回复可被群成员看到，审计记录发送渠道及目标群。

## 查看审计

查询、拒绝与审计查询记录操作者、请求 ID、用途、范围、字段类别、权限依据、目标内部标识、时间、数量、结果及渠道。被拒绝的请求记录原因码，原始查询线索、身份值、材料正文与结果正文不进入日志或审计。

候选和敏感结果在审计提交成功后返回。审计故障时返回 503，不返回敏感数据。查询整体限时 10 秒，审计提交限时 3 秒。审计查询要求独立的 information-query.audit.read 权限。

## 审计保留与维护

审计默认保留 12 个自然月，截止时间按 UTC 当前时间减去配置月数计算。清理严格早于截止时间的记录，恰好位于边界的记录保留。保留规则同时遵循[数据保留与删除](data-retention.md)。

运行身份只获得 information_query schema 的必要读取与追加权限。独立维护身份只获得该 schema 的 USAGE 和 audit 表 SELECT/DELETE，不得 INSERT、UPDATE、执行 DDL 或访问其他业务 schema。启动时验证两类身份的权限隔离。

backend 使用独立维护连接池，最多两个连接。启动立即清理，随后每小时执行，每批最多 1000 条，每次调用限时 5 秒，SQL 限时 3 秒。停止时先取消并等待维护任务，再关闭连接池。

争议保留尚无逐对象自动排除。存在保留义务时，维护人暂停相关清理或采用更早的截止时间，不直接按默认期限删除争议数据。批量预览、导出与恢复演练的实施状态见[后端候选状态](../development/backend-decisions.md)。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| IQ-01：平台管理员从 QQ 查到已关联用户 | 由 qq-binding 解析候选，分别展示来源、当前状态和历史变更，再按业务域查询 |
| IQ-02：学校或群管理员查询对象 | 每个域独立核验学校、群及业务能力，只返回当前授权范围 |
| IQ-03：查询姓名出现多个不同对象 | verification 返回的同名候选分别分组，不拼接成同一人 |
| IQ-04：操作者可查内容但无钱包查询权 | 内容可单独查询，申请未授权钱包域返回拒绝且不返回部分结果 |
| IQ-05：机器人没有该类查询授权 | 不因后台存在相同能力而自动向群或私聊返回结果 |
| IQ-06：展开完整身份字段 | 提供方独立授权，审计提交成功后返回字段，日志不保存身份原值 |
| IQ-07：敏感查看时审计不可用 | 返回暂不可用，不返回敏感结果 |
| IQ-08：群聊管理员查询已获准字段 | 依据请求人权限在原群返回，并记录发送渠道与目标群 |
