# 课程、教师维护与教务导入

## 范围

管理员维护 StuHelper 中用于查询的课程和教师资料，查看教务导入来源、进度及结果。该业务范围已确认；课程与教师概念见[课程规格](academic-content.md)，学生侧入口见[我的课程与课表](my-courses.md)。

## 目录维护

管理员在自己的范围内检索课程与教师，查看课程基本信息、院系、学期、开课和授课关联，维护目录中需要更正或补充的信息。修改前可以看清对象及其关联，避免将同名但不同学校的教师或课程混为一项。

目录信息缺失时保留未知；人工补充和外部导入的关系需要有明确规则，不能让一次导入无说明地覆盖管理员已经确认的更正。具体字段、覆盖规则、合并与停用方式仍需决定。

## 导入管理

管理员可查看已接入来源，查看各次导入任务，并对已启用来源手动发起一次导入。任务显示等待、处理中、成功或失败及可理解的结果，失败不能表现成来源没有数据或所有课程已消失。

导入的业务对象包括学期、课程、教师、开课、时间地点和本人选课关联。来源接入、字段覆盖和同步安排在实际学校接入前确认。维护对象是 StuHelper 的展示资料，不赋予管理员向学校系统执行选课、退课、排课或改成绩的能力。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| CO-01：管理员查找同名不同学校的教师 | 可区分对象及其关联，不自动合并 |
| CO-02：课程信息不完整 | 可看到缺失项并按许可范围补充，不以零或默认值伪造信息 |
| CO-03：手动发起已启用来源的导入 | 可查看该次任务和真实处理结果 |
| CO-04：导入失败 | 说明失败，不把任务显示成成功或将未知状态显示成无课程 |

## 待确认事项

允许人工维护的字段、来源优先级、重复对象合并、目录停用或删除对历史评价和资料的影响、同步频率、批量导入格式及具体管理角色尚待确认。
