# 课程、教师维护与教务导入

## 范围

管理员维护 StuHelper 中用于查询的课程和教师资料，查看教务导入来源、进度及结果。该业务范围已确认；课程与教师概念见[课程规格](academic-content.md)，学生侧入口见[我的课程与课表](my-courses.md)。

## 目录维护

管理员在自己的范围内检索课程与教师，查看课程基本信息、院系、学期、开课和授课关联，维护目录中需要更正或补充的信息。修改前可以看清对象及其关联，避免将同名但不同学校的教师或课程混为一项。

目录信息缺失时保留未知。范围内管理员可补充、更正与合并重复对象，人工确认字段优先于后续导入，冲突展示给管理员处理。合并保留旧链接、评价和资料关联，停用不删除历史。

合并前展示源对象、目标对象及当前修订。合并后使用目标对象的资料，源名称作为别名保留，源记录与历史仍可追溯。源对象的其他字段不自动覆盖目标。确认前任一对象变化时要求重新预览。停用仅从默认目录移除，旧链接和关联仍可查询。

## 导入管理

管理员可查看已接入来源，查看各次导入任务，并对已启用来源手动发起一次导入。任务显示等待、处理中、成功或失败及可理解的结果，失败不能表现成来源没有数据或所有课程已消失。

导入的业务对象包括学期、课程、教师、开课、时间地点和本人选课关联。来源按实际接入能力启用，支持导入预览与手动导入，同步频率由后台配置。维护对象是 StuHelper 的展示资料，不赋予管理员向学校系统执行选课、退课、排课或改成绩的能力。

## 选课与任课记录

课程评价的选课证据由 catalog 提供。学校、课程、学期和教师使用稳定 ID；教学班和教师授课关系保留来源及有效学期。管理员可在授权学校范围内导入教务数据，用户也可授权学校适配服务读取本人教务选课记录。接入方式由私有 campus-adapters 实现。

导入预览区分新增、更正、冲突和未能关联的记录。确认后保存学生账号、课程、学期、任课教师集合、来源标识、获取时间和修订。选课名单与学校会话仅供获准服务使用，公共目录返回课程、教师及开放的开课信息。本人查询只返回自己的选课与教师选项，管理员查询按学校及业务范围授权并记录审计。

同一课程跨学期由不同教师或多位教师合授时，各次任课关系分别保存。教师选项只取本人真实选课记录；评价提交保存采用的来源与教师归属快照。来源更正触发关联复核，既有评价的归属修改保留管理决定。

学校连接暂不可用时，已保存且仍有效的选课证据可继续查询。尚未取得证据的用户看到待同步或同步失败状态。学校凭据的保存与销毁遵循私有适配服务的数据保留规则。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| CO-01：管理员查找同名不同学校的教师 | 可区分对象及其关联，不自动合并 |
| CO-02：课程信息不完整 | 可看到缺失项并按许可范围补充，不以零或默认值伪造信息 |
| CO-03：手动发起已启用来源的导入 | 可查看该次任务和真实处理结果 |
| CO-04：导入失败 | 说明失败，不把任务显示成成功或将未知状态显示成无课程 |
| CO-05：导入本人已选课程及合授教师 | 用户可查询该课程和准确的教师候选 |
| CO-06：下一学期更换任课教师 | 新记录保留新学期，历史评价仍可追溯原来源 |
| CO-07：普通用户请求其他学生的选课名单 | 按数据归属拒绝，响应保持脱敏 |
| CO-08：合并确认重复的课程或教师 | 保留旧链接、开课、选课与评价关联，跨学校操作被拒绝 |
| CO-09：停用目录对象 | 默认列表不展示，历史及旧链接仍保留，可重新启用 |
| CO-10：预览导入后资料发生变化 | 预览不写入业务数据，确认拒绝旧预览并保留人工更正 |

## 配置与后续事项

目录维护规则已经确认。具体字段、导入格式和来源映射在各学校接入实现时定义，遵循人工确认优先、保留关联和失败不清空的规则。管理角色由统一后台规格定义。
