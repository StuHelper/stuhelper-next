# 管理角色与配置操作

## 角色和范围

后台采用可配置角色与范围。初始模板包括平台、学校、内容审核、资料、群和财务管理，权限可以按职责组合。模板名称不自动授予全部能力，操作资格和对象范围分别检查。

平台管理员管理全站，其他管理员只处理获授权的学校、群和业务模块。完整身份字段、认证材料、账务查询、导出和资金操作等敏感能力独立授予，拥有群管理权不能自动取得这些能力。

## 配置操作

页面展示配置当前值、作用范围、规则来源和最终生效结果。管理员修改前能看清影响对象。提交时发现其他人已经修改同一配置，应提示比较差异后重试，不静默覆盖。

各业务规定的参数、启停和动作资格由有配置权限的管理员维护。没有获准范围的管理员不能通过新增规则扩大自己的管理权。

## 操作记录

管理员可在获准范围查看管理操作的对象、操作者、时间、原因与结果。批量操作先预览目标与影响，再执行并逐项显示结果。查询权限不自动赋予修改权限。

查看撤回消息不建立单独业务查看或审计记录，遵循群管理规格。其他管理决定和实际执行结果仍按相应业务记录，日志不复制认证材料或交易载荷。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| AO-01：群管理员请求不在范围内的资料或财务操作 | 拒绝，不因角色模板而扩大范围 |
| AO-02：两名管理员同时修改同一配置 | 后提交者比较冲突后重新提交，不覆盖另一人的修改 |
| AO-03：管理员批量处理多个对象 | 先预览，再逐项显示实际成功或失败 |
| AO-04：查询角色希望执行退款或修改认证 | 另行检查操作权限，查询权不能代替操作权 |
