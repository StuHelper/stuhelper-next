# 第三方开放平台

## 范围

保留开发者应用接入、管理审核、用户授权和学生状态等业务信息查询。该范围与初始字段已确认，接口协议在实现阶段定义。开放平台与独立 SSO 的登录能力是不同服务。

## 目标业务流程

1. 开发者提交应用资料、用途和申请使用的业务信息范围。
2. 管理员查看接入申请，批准或反馈需要修改的内容。
3. 用户看到应用身份和申请获取的信息，决定是否授权。
4. 获得授权的应用可读取约定范围内的学生状态等业务信息。
5. 用户在个人中心查看已授权应用并取消授权；应用随后不能继续取得该项已撤回的业务信息。

登录到一个应用不自动授权其读取学生信息。取消应用业务授权也不等同于注销 SSO 账号、撤销学生资格或删除用户在其他系统中的业务数据。

## 信息范围

初始可申请学生认证状态、所属学校及单独授权的 QQ 绑定信息，不开放证件、认证材料或钱包原始记录。已登录开发者可提交应用申请，管理员审核用途和信息范围，用户逐项同意。授权期限与调用配额由后台配置，收费方案独立延期。

## 管理与用户界面

开发者可以查看应用接入状态和获批范围；管理员处理应用申请；用户在授权页理解用途，在已授权应用列表查看和取消授权。应用停用、用户撤回或授权到期后停止相应查询。

第三方需停止使用相关已取得数据，并按约定删除，协议明确依法必须保留的例外。平台记录通知与应用反馈的处理结果，不能把通知已送达等同于第三方已实际完成删除。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| OP-01：应用申请读取学生状态 | 进入审批，未获批不显示已开通 |
| OP-02：用户同意某个获批信息范围 | 应用只取得用户同意且平台批准的范围 |
| OP-03：用户拒绝或取消授权 | 不继续提供相应业务信息，不替用户注销其他账号 |
| OP-04：应用能通过 SSO 登录但未获业务授权 | 登录能力不自动变成学生信息查询权限 |

## 配置与后续事项

接入、授权、初始字段和撤回后的处理规则已确认。商业收费由项目负责人明确延期。具体接口字段和配额配置在实现时按上述范围定义。
