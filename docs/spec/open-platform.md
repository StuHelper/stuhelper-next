# 第三方开放平台

## 范围

保留开发者应用接入、管理审核、用户授权和学生状态等业务信息查询。该范围与初始字段已确认，接口协议在实现阶段定义。开放平台与独立 SSO 的登录能力是不同服务。

## 目标业务流程

1. 开发者提交应用资料、用途和申请使用的业务信息范围。
2. 管理员查看接入申请，批准或反馈需要修改的内容。
3. 用户看到应用身份和申请获取的信息，判断是否授权。
4. 获得授权的应用可读取约定范围内的学生状态等业务信息。
5. 用户在个人中心查看已授权应用并取消授权；应用随后不能继续取得该项已撤回的业务信息。

登录到一个应用不自动授权其读取学生信息。取消应用业务授权也不等同于注销 SSO 账号、撤销学生资格或删除用户在其他系统中的业务数据。

## 信息范围

可申请学生认证状态、所属学校、QQ 绑定、个人资料、课表、目录和公开评价，各项分别审批，用户逐项授权。不开放证件、认证材料或钱包原始记录。目录和公开评价还要求授权用户当前通过内容准入。权限使用稳定标识，字段由当前 OpenAPI 定义。已登录开发者可提交应用申请，管理员审核用途和信息范围，用户逐项同意。授权期限与调用配额由后台配置，收费方案独立延期。

QQ 授权分为“绑定状态”和“绑定状态和 QQ 号码”两档，分别申请、审批和授权，同意页显示具体档位。不提供只有号码的范围。两档从 qq-binding 读取当前三项完成状态。详情档只在三项全部完成时返回 OneBot QQ 号，不返回 openid 或 unionid。缺少任一项按未绑定处理，来源不可用返回 503。

## 管理与用户界面

开发者可以查看应用接入状态和获批范围；管理员处理应用申请；用户在授权页理解用途，在已授权应用列表查看和取消授权。应用停用、用户撤回或授权到期后停止相应查询。管理员停用应用时撤销原授权，重新启用后需要用户重新授权，旧访问令牌不能恢复。

开发者注销业务账号时停用其名下应用并撤销全部用户授权，重新接入交由管理员处理。

第三方需停止使用相关已取得数据，并按约定删除，协议明确依法必须保留的例外。平台记录通知与应用反馈的处理结果，不能把通知已送达等同于第三方已实际完成删除。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| OP-01：应用申请读取学生状态 | 进入审批，未获批不显示已开通 |
| OP-02：用户同意某个获批信息范围 | 应用只取得用户同意且平台批准的范围 |
| OP-03：用户拒绝或取消授权 | 不继续提供相应业务信息，不替用户注销其他账号 |
| OP-04：应用能通过 SSO 登录但未获业务授权 | 登录能力不自动变成学生信息查询权限 |
| OP-05：用户授权目录和公开评价但未通过内容准入 | 应用读不到这些内容 |

## 配置与后续事项

接入、授权、初始字段和撤回后的处理规则已确认。商业收费延期。具体接口字段和配额配置在实现时按上述范围定义。

## 接口与数据投影

| 稳定范围 | 返回字段 | 提供方 |
| --- | --- | --- |
| student_status | 当前是否具有学生校园资格、评估时间 | verification |
| schools | 当前有效资格所属学校 ID 与名称 | verification |
| qq_binding_status | 是否已绑定 | 可信 QQ 绑定提供方 |
| qq_binding_details | 绑定状态、已绑定号码 | 可信 QQ 绑定提供方 |
| profile | 公开资料 ID、昵称与简介 | profiles |
| schedule | 本人有效选课 ID、课程、学期、教学班、已知排课与来源更新时间 | catalog |
| catalog | 当前可见目录的 ID、名称及目录字段 | catalog |
| public_reviews | 当前可见评价正文、目标、评分与发布时间 | reviews |

课表返回当前导入来源提供的排课，未提供时 meetings 为空，不能据此判断用户空闲。个人日程编辑和日历导出不在本次开放平台实现中。QQ 未接入可信来源时返回 503，不返回伪造的未绑定状态。

业务令牌只关联授权用户，不接受目标账号参数。目录和公开评价读取前由提供方检查当前准入，其他范围继续执行各自归属与账号状态检查。响应只含当前请求的单个范围，不夹带证件、实名脱敏值或内部身份键。

授权请求绑定用户、应用修订、精确 HTTPS 回调、逐项范围、state 和 PKCE S256。授权码单次使用且有效 60 秒。后台设置授权期限、令牌期限和 UTC 日配额，访问令牌最长一小时，不发行刷新令牌。

每账号最多 100 个应用和 100 个未过期的待处理授权请求。列表每页最多 100 条，通知每批最多 100 条。业务查询在提供方调用前后重查授权，撤回后丢弃已经取得但尚未返回的数据。

应用凭据仅首次轮换返回，数据库只保存哈希。已停用应用仍可用凭据读取停止使用通知并回报处理结果，业务令牌不会恢复。通知的 seen_at 和第三方声明分别记录。

| 补充场景 | 预期结果 |
| --- | --- |
| OP-06：读取期间撤回授权 | 已取得的数据不返回，旧令牌后续继续被拒绝 |
| OP-07：停用后重新批准应用 | 旧授权不恢复，用户重新逐项授权 |
| OP-08：开发者完成业务账号注销 | 名下应用停用，所有用户授给这些应用的权限停止使用，通知继续处理 |
| OP-09：第三方回报删除结果 | 保存 received、deleted 或法定保留理由，区别于通知读取记录 |

授权码被重复交换时，服务端先核验应用、回调和 PKCE，再撤销该授权码已签发的令牌。个人资料范围的 id 与 subject 相同，按应用区分，不返回全局主页 ID。

后台每五秒尝试到期清理，每类最多 100 条、总计最多 600 条，单轮最长五秒。失败回滚整轮删除并保留后续重试，保留期见[数据保留](data-retention.md)。
