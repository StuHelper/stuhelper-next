# 个人日程与 DDL

## 范围与适用情况

planner 模块管理本人的日程、DDL、个人课表更正和空闲时间，当前尚未实现。用户可以在页面操作，也可以授权 Agent 操作。

DDL 是用户自己的待办截止时间，来源为手动创建、对话创建或日历导入。planner 不提交或批改作业，不连接学校作业系统。可信选课记录仍由 catalog 管理，个人修改不影响评课资格。

## 术语与行为规则

| 对象 | 规则 |
| --- | --- |
| 个人日程 | 保存标题、开始和结束时间、时区、重复规则、地点、来源和修订号 |
| DDL | 保存标题、截止时间、时区、关联课程、完成状态、来源和修订号 |
| 课表更正 | 引用 catalog 的课程或教学班，只改变本人展示和空闲时间计算 |
| 空闲时间 | 由课表、个人日程和用户指定的时间范围计算得出 |

- 列表按时间排序，设置分页和单页上限。用户只能读写本人的记录。
- 修改使用修订号。版本冲突时返回当前内容，由用户选择保留哪一版。
- 导入与现有个人修改冲突时，由用户选择保留或替换，不静默覆盖。
- 日期和时间按用户时区显示，存储时保留时区。“明天”等相对时间由服务端按当前时区解析，并在预览中显示实际日期。

## 空闲时间

空闲时间由代码计算，模型只转述结果。结果分为空闲、忙碌和不确定三类。只有能证明没有课程和日程的时段才算空闲。已知的课程和日程始终算忙碌，其余无法证明的时段标记为不确定，并说明原因。

课表快照记录覆盖的学期和日期、同步是否完整、更新时间。快照满足三个条件才算有效：覆盖查询日期、同步完整、数据年龄不超过后台配置的上限。catalog 不可用时可以继续使用有效快照，结果显示更新时间。

某门课时间未知时，该课程所在学期内未被已知安排占用的时段都标记为不确定。用户更正该课程时间后，结果恢复正常。

## 接口、状态与失败语义

创建和修改接口支持 `Idempotency-Key`。相同键和相同内容返回原结果，相同键对应不同内容返回 409。

## 提醒

planner 持有提醒计划，每条计划绑定日程或 DDL 的修订号。到期时，planner 先检查最新状态，再把发送意图交给 notifications。发送意图使用计划 ID 和修订号去重，投递失败不影响日程和 DDL 的写入结果。

改期会按新时间重建计划。完成、删除或取消提醒会使旧计划失效。旧事件迟到时按修订号忽略。已经交给外部渠道的提醒无法收回。

服务恢复后，日程尚未开始、DDL 尚未截止的提醒照常发送并标明延迟，其余提醒不再发送，只记录结果。

## 模块状态

planner 关闭时，日程和 DDL 工具不可用，数据保留，到期提醒不再发送。notifications 不可用时，提醒按上文规则恢复。

## 行为场景与验收

| 场景 | 预期结果 |
| --- | --- |
| PL-01：用户创建 DDL | 保存本人记录，并在近期 DDL 中显示 |
| PL-02：用户询问未完成的 DDL | 只返回本人未完成的 DDL，按截止时间排序 |
| PL-03：其他用户读取该 DDL | 按对象不存在处理，不泄露内容 |
| PL-04：同一幂等键重复创建 | 只保存一条记录，并返回原结果 |
| PL-05：两端同时修改同一日程 | 后提交者收到冲突和当前内容，不静默覆盖 |
| PL-06：课表快照有效且课程都有结构化时间，查询当天空闲时段 | 上课时段显示忙碌，其余时段显示空闲 |
| PL-07：某门课时间未知 | 已知安排显示忙碌，学期内其余时段显示不确定 |
| PL-08：catalog 不可用且没有已保存课表 | 返回不确定或依赖不可用，不显示全部空闲 |
| PL-09：跨时区用户查询“明天” | 按用户时区解析，并显示实际日期 |
| PL-10：个人更正课程时间 | 只影响本人课表和空闲时间，可信选课记录和评课资格不变 |
| PL-11：导入与个人修改冲突 | 用户选择保留或替换，未选择前不覆盖 |
| PL-12：课表快照超过数据年龄上限 | 已知安排保留，其余时段显示不确定 |
| PL-13：课表只同步了部分课程 | 其余时段显示不确定，不显示空闲 |
| PL-14：查询日期超出快照覆盖的学期 | 该日期显示不确定，不沿用其他学期课表 |
| PL-15：学校调课后尚未同步 | 新快照生效前结果显示更新时间；同步后按新时间计算 |
| PL-16：提醒发送前 DDL 改期 | 旧提醒不发送，按新时间提醒 |
| PL-17：提醒发送前 DDL 完成或删除 | 不发送提醒 |
| PL-18：旧修订号的事件迟到 | 被忽略，不恢复旧提醒 |
| PL-19：重复处理同一提醒计划 | 只产生一条发送意图 |
| PL-20：停机恢复后存在到期提醒 | 仍有意义的提醒标明延迟发送，已过期的不发送 |
