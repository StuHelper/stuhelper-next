# 文件与媒体模块

## 数据与接口

media 承接通用文件入口，拥有上传会话、逻辑版本、完整性摘要、内容类型、可用状态和业务引用。课程资料、用户资料及其他文件业务通过公开接口使用它，各自拥有业务描述、访问权和发布决定。

上传依次经历已创建、传输中、待校验、可引用、已引用、已取消或已过期。完成校验包括实际大小、摘要、允许类型和来源约束。需要审核的业务先保存待审引用，审核通过后开放对应使用。类型和容量参数由后台配置，配置完整后开放上传。

## 引用与下载

业务提交使用上传会话和引用操作 ID，重复提交返回同一引用。模块释放引用时 media 检查其他有效引用，无引用对象按清理任务删除。删除原始业务内容同时撤销相关下载入口。

受限文件只放入获准承载其分类和范围、满足保护要求的实例，下载签发前检查当前业务授权。平台或用户来源不自动决定密级准入。签名期限、临时对象和取消重试按[模块通信规格](module-protocol.md)执行，下载名称保留原名并安全编码。

## 存储与运营

存储后端以独立 adapter 接入，首期实际候选为 BHpan，后续可使用 S3、COS 等。通用存储服务负责实例、准入、容量和副本，文件服务通过接口使用它；backend 注入实现，公开接口不暴露供应商特有类型。

用户贡献和激励分别作为扩展。贡献扩展协调同意、额度、期限和退出，奖励由获准统计和业务事件驱动；通用存储不依赖课程或奖励。关闭这些扩展后，平台实例和其他文件业务仍可服务。

当前方案只覆盖账号与文件层故障，不考虑 BHpan 整体服务故障。详细边界见[存储架构](../design/storage-architecture.md)、[放置规格](storage-placement.md)与[贡献规则](storage-contribution.md)。存储核心已独立实现，media 的逻辑版本、上传会话与业务引用接口仍待实施；正式装配尚未完成。

未来在线阅读器、加密容器和溯源是可选的[文件保护与交付能力](../design/file-protection-and-delivery.md)，本轮仅保存设计，不要求普通文件下载使用专用客户端。文件不可用、无权访问和交付方式不受支持分别表达。

| 场景 | 预期结果 |
| --- | --- |
| MEDIA-01 | 上传完成请求重试时，产生同一引用结果 |
| MEDIA-02 | 文件校验失败时，保持隔离状态并报告原因 |
| MEDIA-03 | 删除一个引用时，其他有效引用仍可使用对象 |
| MEDIA-04 | 文件被停用后，签发入口立即停止，现有签名按期限失效 |
