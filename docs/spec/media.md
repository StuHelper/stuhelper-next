# 文件与媒体模块

## 数据与接口

media 承接通用文件入口，拥有上传会话、不可变版本、完整性摘要、内容类型、可用状态和业务引用。课程资料、用户资料及其他文件业务通过公开接口使用它，各自拥有业务描述、访问权和发布决定。

用途由服务端配置，固定所属业务、类型、大小与保护要求；客户端不能指定供应商账号或密级。上传实际类型、长度和 SHA-256 校验通过后等待独立业务批准，校验不代表恶意内容扫描或课程审核。

文件保持稳定 ID，版本绑定上传者、名称、类型、长度和摘要。重试复用同一上传，参数改变被拒绝；新版本不替换旧版本的引用，跨上传者不能追加版本。单文件上限 1 GiB，实际大小与类型限制由用途进一步收紧。

上传状态依次为 created、uploading、verifying、awaiting_approval、approved、ready。cancelled、expired、rejected、deleting、deleted 停止交付；物理清理完成单独表达，不能将停止访问计为远端文件已删除。

## 隔离与发布

待审内容使用非公开分类，仅进入明确获准保管明文的平台实例。发布分类可以保持原分类，或在同一学校或组织范围内改为公开。共享引用转换时保留来源，待目标保护分组完成内容校验后再切换。旧版对象原地公开化仍要求来源实例同时获准承载新旧分类。

批准与存储就绪分别判断。首次引用发布至少需要两份独立健康副本，目标三份由存储异步补齐。业务依然必须检查自己的审核、积分、会员或内部权限，存储门槛不授予业务权益。

## 引用与下载

引用固定到版本、业务模块和业务对象，同一绑定不重复创建。引用模块须与上传用途一致，跨业务复用另建版本。pending、publishing 不允许读取，active 才开放，released 不可复活。

发布先持久化意图，再检查当前业务授权及副本门槛，最终确认引用。响应丢失后仍需获准请求重试；后台只恢复存储操作，不凭历史授权自动开放引用。业务授权器必须使用当前资格与业务状态。

下载仅通过引用网关。存储核验完整内容后，media 在首字节前重新检查停用、引用、分类及当前权限。文件名安全编码，响应为附件并禁止缓存和 MIME 嗅探；不返回供应商地址、匿名直链或离线许可。

释放引用立即停止该入口，其他有效引用继续使用同一版本；最后一个引用释放后进入持久清理。有有效引用时拒绝整文件删除，文件停用阻止新上传、引用和下载。迟到结果不得复活已取消版本。

受限文件只放入获准承载其分类和范围的实例。应用层加密延期，受限明文当前只使用明确获准的平台私有实例；用户实例的密文正向场景尚未开放。具体放置规则见[存储规格](storage-placement.md)。

## 持久化与恢复

media 使用自己的迁移和受限数据库身份，不读取 storage 表。逻辑文件、版本、引用、任务、请求重放、审计与 outbox 均由本模块拥有；状态与事件在同一事务提交。传输不持有长期数据库事务。

任务有持久化租约、执行代次和明确重试上限。存储对象使用绑定服务身份与版本的稳定键，普通幂等窗口过期也不会重复创建。删除先停止交付，再释放本版本的存储引用。其他引用仍使用内容时保留副本；最后一个引用释放后，确认物理删除再报告清理完成。

上传窗口和未引用保留窗口由服务端配置，均不超过二十四小时；后者不得短于前者。未引用内容到期后清理，避免业务长期挂起孤儿文件。文件、版本、引用和并发各有配额，上限见[模块规格](https://github.com/StuHelper/stuhelper-media/blob/codex/media-services/docs/spec/media.md)。

本模块复用 storage 暂存，不新增文件字节缓存。数据库墓碑、请求重放与审计暂未自动归档；生产前须配置数据库容量及保留清理方案，达到限额不得自动扩容。

## 存储与运营

存储后端以独立 adapter 接入，首期实际候选为 BHpan，后续可使用 S3、COS 等。通用存储服务负责实例、准入、容量和副本，文件服务通过接口使用它；backend 注入实现，公开接口不暴露供应商特有类型。

用户贡献和激励分别作为扩展。贡献扩展协调同意、额度、期限和退出，奖励由获准统计和业务事件驱动；通用存储不依赖课程或奖励。关闭这些扩展后，平台实例和其他文件业务仍可服务。

当前方案只覆盖账号与文件层故障，不考虑 BHpan 整体服务故障。详细边界见[存储架构](../design/storage-architecture.md)、[放置规格](storage-placement.md)与[贡献规则](storage-contribution.md)。

stuhelper-media 已提供上述公开接口、Go/TypeScript SDK 和 PostgreSQL 实现。backend 显式启用 media 后注入独立存储服务身份、当前授权与数据库配置，启动恢复循环。隔离环境使用认证和供应商夹具，Next SSO 保持不动。

未来在线阅读器、加密容器和溯源是可选的[文件保护与交付能力](../design/file-protection-and-delivery.md)，本轮仅保存设计，不要求普通文件下载使用专用客户端。文件不可用、无权访问和交付方式不受支持分别表达。

| 场景 | 预期结果 |
| --- | --- |
| MEDIA-01 | 并发重试复用同一版本，参数冲突被拒绝，错误内容不写入供应商，过期上传可清理 |
| MEDIA-02 | 待审内容保持隔离，批准后补齐三份，引用独立释放并完成最终删除 |
| MEDIA-03 | 版本不可变，拒绝跨用户及跨业务绑定，撤权或停用阻止下载首字节 |
| MEDIA-04 | 丢失响应后恢复同一对象，后台不自动发布引用，获准重试才完成发布 |
| MEDIA-05 | 数据库身份隔离、审计与事件同事务，有引用时拒绝整文件删除 |
| MEDIA-06 | 生成 SDK 完成上传下载，拒绝客户端密级及未认证请求，正确编码名称且不暴露物理位置 |

## 内容去重与免上传

新版本使用共享存储引用，独立保存上传者、文件名、审核与业务绑定。reuse_existing 开启本人免上传，服务检查已完成内容、当前读取权限、相同用途配置、内容类型、摘要、长度和保留期限，最多查询十个匹配候选。

reused 为 true 且状态为 verifying 时，客户端查询原会话，不重复发送内容。成功后进入 awaiting_approval，新版本仍独立审核。跨用户仅提交摘要必须实际上传，通过校验后才可共享物理副本。

同一保护分组仅保留一组副本。不同保护要求可能在转换期间各有一组副本，目标校验成功后释放来源引用。旧版存储对象不自动改写，历史内容批量归并另行处理。

| 场景 | 预期结果 |
| --- | --- |
| MEDIA-11 | 本人内容免上传，版本与审核独立；跨用户摘要不能取得内容，实际校验后可共享物理副本 |
| MEDIA-12 | 权限、停用和配置变化使来源不再可复用；响应丢失、重启及取消保留原标识和其他引用 |
