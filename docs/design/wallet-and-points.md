# 积分、Ivory 与资料解锁

## 目标与边界

为日常参与、内容贡献和资料消费提供一致的账户体验。采用两套账户：积分与 Ivory 充值余额，用户可分别查看余额、来源和消费记录。积分名称就是“积分”，获取方式不限于贡献；Ivory 的命名取“象牙塔”的校园意象。

本设计只定义业务关系，不实现支付渠道、账本数据库或第三方收付款。已确认规则与验收集中在[积分与余额规格](../spec/wallet-and-points.md)。

## 三类业务事实

| 概念 | 解决的问题 |
| --- | --- |
| 积分与充值余额 | 用户有多少可用额度，来自哪里，何时消费或退款 |
| 资料访问权 | 用户当前为什么可以下载某份资料，例如管理员范围、单独授权、群体权益或购买解锁 |
| 上传者奖励 | 哪一次内容或其他贡献符合奖励条件，应获得多少积分 |

资料消费由平台收取或消耗，上传者根据贡献规则另获奖励，不直接把每次购买拆分给上传者。作品许可、上传者奖励与用户下载权分别表达，避免把上传原创等同于必须按下载分成。

## 用户体验

用户查看积分时能区分长期积分和限时积分，了解即将到期的数量；查看余额时能知道充值、购买积分、资料消费和退款记录。余额不过期；积分期限由规则配置。

用户可用余额购买积分，积分不能反向兑换余额，两者均不能转赠或提现。充值退款是退回符合条件的已充值资金，不等同于把积分、奖励或消费收入兑换为现金。

充值余额按 Ivory 展示，CNY 充值采用 1 CNY = 1 Ivory。USDT 充值是已确认需要支持的方向，但汇率、网络、手续费、到账及退款折算后续确定。显示支付币种与 Ivory 入账数量时不能将两者混作同一种单位。

资料页面分别说明当前学生资格是否满足、是否已有访问权。普通用户需要有效学生资格，即使已有单独授权、会员权益或购买解锁也不能跳过；管理员只在自己的管理范围内例外。一次解锁长期覆盖同一资料及后续版本，资格失效暂停下载而不抹去解锁权益，恢复资格后不重复收费。

## 退款路径

用户提交退款申请并查看进度。支持原路退款的收款渠道优先原路退回；不能原路退回时，进入人工退款，用户补充收款码或收款账户，由管理员处理并反馈结果。不能把提交了收款信息显示成退款已经完成。

积分或余额消费退款退回原支付账户，并处理对应解锁权益。积分退款保留原类型和有效期，实际到账时已过期的部分不恢复为可用积分，也不增加宽限期。退款不应撤回用户通过其他有效来源取得的权益，但实际下载仍须符合资料访问条件。

## 管理体验与待确认事项

需要积分规则、账户流水、资料价格和退款处理界面；与资料访问管理联动，避免要求管理员先理解底层权限系统才能给用户授权。具体奖励数值、积分售价、期限与会员套餐是可继续配置或讨论的产品规则，未确认项见规格。
