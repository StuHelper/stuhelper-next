库在失败重登时清除原会话。重新授权应使用隔离的新客户端验证，成功后切换凭据修订，不能在仍服务任务的客户端上尝试登录并破坏原会话。供应商授权状态与平台是否允许新写分别处理。

固定提交的 `auth.go` 在一个 SSO 登录回调分支调用 `refreshToken`，随后读取 token 并查询文档库验证会话；这不证明后台可持续续期。`client.go` 仅持有内存会话，未提供持久化或公开续期入口；`Close` 只清除本地状态，不等于供应商撤销授权。

backend 已实现加密托管凭据及重启后重新登录，随后由连接层恢复同一账号与专用根。三个真实账号已通过此恢复路径。长期观测已记录活跃账号失效后的自动重登，随后因关机中断。获准恢复后三账号重登及三副本校验通过；完整二十四小时试次和无密码续期仍待验收。

## BHpan 持续授权验证方案

持续可用要求同时满足用户或平台仍同意使用、供应商授权仍有效、当前操作权限及实例准入仍有效。登录成功只验证一个时点，不能证明未来可用；平台自有和用户贡献账号均须验证，贡献同意与供应商令牌也不能互相代替。

以下计划已完成短时观测、凭据重登、跨进程恢复、平台停用与续授验证。活跃账号已出现会话失效和自动重登，精确失效原因、闲置结果与无密码续期仍待核实。学校临时会话、BHpan 访问令牌与续期材料分别验证。

长期存储托管允许在账号拥有者明确授权的期限内保存所需凭据，具体边界见[数据保留规则](../spec/data-retention.md)。一次性学校认证的十五分钟限制不套用于长期托管；依赖学校密码的 BHpan 重新登录须有明确用途授权。

| 验证项 | 操作与证据 |
| --- | --- |
| 授权材料与权限 | 分别记录 SSO 和本地账号所需材料类型、供应商声明期限及可用操作；核实是否存在专用令牌和目录级权限，不保存原始响应到日志 |
| 闲置与活跃到期 | 在互不干扰的独立试次中比较不访问和低频访问；闲置会话仅在观察终点探测，避免探测本身续命。记录最后成功、首次失败与错误类型 |
| 无密码续期 | 跨过实际访问令牌期限后，使用已核验机制续期并读取受保护资源；确认新材料替换、旧材料行为及重复续期，不以 HTTP 200 或令牌字符串变化认定成功 |
| 凭据重新登录 | 用获准托管的账号凭据创建新客户端，确认同一稳定账号、专用根与受保护资源后切换；遇到验证码或密码失效进入待重新授权，不无限重试 |
| 重启与并发 | 保管规则明确后验证最小材料恢复；同账号并发续期只执行一次，轮换失败或旧进程回执不得覆盖新凭据修订 |
| 撤销与重新授权 | 隔离测试供应商支持的撤权、会话到期及 StuHelper 停用；分别验证停止新请求、在途结果隔离和重新授权，不把本地 Close 当作远端撤权 |
| 操作范围与内容 | 登录和续期后读取专用根、容量及无敏感测试对象；后续写权限演练只在专用根创建、回读校验及删除小文件，不触及个人文件 |
| 故障分类 | 区分 401、403、登录页伪成功、限流、网络超时和验证码；超时不直接判定撤权，权限拒绝不触发反复重登，需交互时进入待重新授权 |

按供应商声明及实测期限设计跨期观察；声明不清时可先观察三十分钟、两小时和二十四小时，再做三至七天稳定性试验。这些窗口是测试建议，不是凭据保存上限、令牌寿命或长期可用承诺。验证记录区分原会话续期和使用托管凭据重新登录。

真实验证只使用获准测试账号和隔离根。改密、注销其他设备等会影响正常使用的动作另行安排。短时文件演练结束后清理材料；长期观测使用明确期限的临时密文托管，期限与供应商会话寿命分别记录，未观测到真实到期时不能声称续期成功。

结论按实际证据分为可自动续期、可用托管凭据重新登录、需要人工重新授权、无法满足持续接入四类。自动恢复需重复验证、获准材料可恢复、停用可阻止后续使用且故障不会无限重登；需要人工授权时单独评审运营可接受性。

运行时由凭据管理负责材料保管与轮换，adapter 只执行经验证的供应商协议，存储核心消费授权状态及修订。失效后停止依赖该凭据的操作与新放置，从其他健康副本读取或修复；网络故障退避探测，禁止无限重试续期。

### 在线托管入口

首次接入、凭据更新和原申请恢复已实现。存储模块保存归属、同意、操作状态、审计与 outbox；backend 在同一凭据库所有者进程提供隔离登录、建根及双修订切换。贡献、奖励和课程模块均不处理密码。

新账号先登记为暂停、零贡献额度。本人单独选择贡献容量；管理员托管页面只查看脱敏申请和恢复原操作。错误密码不覆盖旧材料，更新保留原根、副本、贡献条件和准入。当前应用登录及真实账号的新增入口尚未验收。

申请全局上限一千条，绑定全局一百个、每人五个。每申请最多五次执行，同一用户五分钟最多五次执行，预算随数据库保留；接口没有自动扩大次数或创建新目录的兜底。历史申请归档与跨进程凭据服务另行实施。

私有凭据库每条最多保留一个活动修订及一个候选修订，单份明文上限 16 KiB、密文文件上限 64 KiB。提交实例后清除旧材料，撤销清除两份并递增撤销标记，迟到核验不能复活已撤销托管。到期沿用既定清理周期。

/storage-accounts 用户页提交后清空账号和密码，未知结果只查询原申请标识。管理员页没有凭据输入，可按原修订恢复。两端均支持八语言、键盘操作、移动布局、空数据、失败恢复和撤权清空，SDK 与契约固定到同一 storage 提交。

本轮真实 PostgreSQL、凭据库与供应商夹具覆盖并发幂等、账号去重、失败保留旧凭据、重启恢复、撤销竞态和登录预算。在线托管实现未触碰原观测试次；关机后的真实恢复按上述单独授权及源码组合记录。

账本已提交而候选凭据尚未激活时，该实例临时拒绝传输。恢复原申请会核对已提交修订，再激活候选；不会新建目录或自动扩大用户授权。
