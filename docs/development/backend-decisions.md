# 后端候选实施状态

## 当前实现

教师认证、内容准入、本人记录、资料访问、个人主页、注销、收藏与开放平台候选已实现、待合并。favorites 与 open-platform 为独立模块，各自拥有仓库、数据和接口。实际源码组合由 workspace.lock.json 记录，正式后端依赖由 backend/go.mod 固定。

| 模块 | 当前能力 |
| --- | --- |
| verification | 教师本人申请、补充材料、人工审核与多档案绑定；档案只能属于一个账号；本人实名字段由服务端脱敏 |
| catalog、reviews | 当前内容准入、本人记录名称与经过验证的草稿关联；公共详情继续执行当前授权 |
| moderation | 新举报要求内容准入；认证失效后仍可补充本人处理中举报的证据，只返回本人回执 |
| resources | 预览与下载同权；投诉只需登录，提交时通过准入才保存标题快照；购买延期 |
| profiles | 昵称 20 和简介 120 个 Unicode 码点；主页展示开关、7 天注销冷静期与可恢复处理进度 |
| favorites | 课程、教师与资料收藏、按目标集合查询本人收藏状态，以及收藏夹管理 |
| qq-binding | 三项独立验证、私聊一次性码、直接 QQ OAuth、解绑与注销、审计及 outbox；私有仓库 StuHelper/stuhelper-qq-binding |
| open-platform | 应用审批、逐项同意、PKCE、短期令牌、撤回和通知反馈 |
| billing | 积分与 Ivory 分账、余额和明细、奖励与追回、用户支付指引、充值确认、取消与到期、购买积分、退款和注销结清；真实支付未接入 |

学校、认证徽章、学院、署名评价和资料默认公开，年级默认关闭。姓名显示末字，证件号显示首尾位，星号数量等于遮住的码点数。姓名少于 2 个码点或证件号少于 3 个码点时拒绝提交。

## 验证与剩余工作

已有提供方的 PostgreSQL CI 已通过。qq-binding 的 GOWORK=off 本地检查与 Koishi 测试通过；backend 的 go.work 数据库组合测试通过。backend 已改为引用私有仓库中的 qq-binding 候选，正式 CI 需要 MODULES_READ_TOKEN 能读取该仓库。

数据库验证使用隔离 PostgreSQL 和模块运行身份。模块场景与测试函数登记在 architecture/modules.yaml。

QQ 绑定状态与绑定状态和号码分别授权。公开主页仅对可信代理解析转发地址，按客户端地址使用进程内单一限流器，多实例各自计数。QQ 来源接入本地 qq-binding 候选；缺少模块或数据库故障返回 503。真实支付、真实账号、发行与部署未验收。会员交易、会员权益及资料购买未提供。

Web 候选已接入收藏、QQ 三项绑定、账号与安全、个人资料、积分与 Ivory、授权应用、开放平台开发者页、`/oauth/authorize` 授权页和教师认证页。授权页读取 OAuth 授权码参数，要求 PKCE S256，用户逐项勾选后才可同意。

钱包页只列出服务端启用的充值渠道。没有启用的渠道时，页面不提供充值入口。各页面都有八语言单元测试和浏览器测试，客户端语言配置与 architecture/locales.yaml 一致。

公共集成按新版 Web 与管理端界面验证评课场景，22 个场景在八语言桌面与移动视口共 352 项检查通过。

教师认证页让教师选择学校、拍照提交证明，并自行选择公开姓名、教师身份、性别和任职单位。认证通过后，教师可以随时修改公开信息。

管理端已接入 QQ 绑定处理、开放平台应用审核、教师认证审核与教师资格撤销，以及账务管理。账务管理包括退款审核与人工打款登记、按账号查询余额与明细、积分购买退款、奖励发放与撤销，以及渠道、积分方案和奖励规则配置。

billing 的配置版本冲突返回 billing_conflict，账号注销冲突返回 billing_closure_conflict。支付自动查询耗尽后订单进入 needs_review，由管理员登记核实结果或安排再次查询。

Web 已接入通知页面，管理端已接入角色授权与操作记录页面。真实 QQ 互联、机器人与支付流程尚待验收。

backend 当前按固定间隔扫描生成通知，这种做法不符合模块通信规格。后续改为业务事务写入 outbox，提交时用 pg_notify 唤醒转发进程，并每 60 秒按未发送索引补查。

部分模块尚未提供公共操作记录查询，平台汇总时会把这些模块列为缺失。信息查询、群组、搜索和结构化课表正在开发。

## 合并依赖

先合入提供方，再将 backend 固定到可拉取的合并提交并验证正式组合。Web/Admin 完成契约与行为接入后验证公共应用组合。所有候选为草稿，合并、发行与部署另行授权。

充值返回公开支付指引，只有提供方查询或验签回调确认成功才入账。取消先核实付款状态并关闭未付款支付单。开发环境提供模拟付款与失败入口，生产配置拒绝启用。

qq-binding 的模块检查在本仓库 CI 中使用隔离 PostgreSQL 运行。QQ 登录、真实机器人、真实 QQ 互联与群服务事件投递未验收。

账务管理读取提供退款列表、包含停用项的渠道、方案与最新规则，以及按账号查询的钱包、最近订单和明细。读取要求 billing.manage，分页上限 100，账号数据与审计同事务返回。billing 独立检查和 backend 固定远程依赖的 GOWORK=off 完整检查通过。接口由私有 billing 仓库的 OpenAPI 定义。
