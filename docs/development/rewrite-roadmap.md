# StuHelper Next 重写路线

## 目标、范围与进度

进度：进行中。工程基础、模块边界与业务规格已建立，可运行框架见[框架工作记录](framework-bootstrap.md)，工程检查见[检查指南](../guide/repository-checks.md)，已确认的旧业务与货币设计见[业务整理记录](business-design-extraction.md)；后端认证、目录、评价、资料、个人主页、收藏与开放平台候选已实现、待合并，完整账务待完成。Next 是重构版本的过渡名称，后续改名与旧仓库退役仍待迁移完成后单独执行。

## 当前交付安排

当前只推进 Web 和 stuhelper-admin，完成已确认的校园业务及模块协作。微信小程序、Android、iOS、HarmonyOS 与独立社交模块暂时搁置，重新启动时另定实施计划。后续端的参考设计继续保留。

| --- | --- | --- |

## 旧数据迁移范围

开发阶段使用最终数据结构，不保留旧 SSO 或学生认证的兼容结构。新系统完成后，独立迁移任务将旧 SSO 账号和学生认证数据转换为新系统结构，再执行核对与导入。具体转换与切换方案由迁移任务维护。

其他旧业务数据不进入新系统的迁移范围。旧课程评价、资料、互动、群与账务数据继续留在旧系统，本轮没有删除、清理或改写。正式退役的处理安排须在实际切换时另行确认。

迁移先进行只读导入、映射与差异核对，再制定切换和恢复方案。生产数据搬运由独立迁移任务执行。

原生端与社交暂时搁置。课程评分维度、导师模板、匿名与署名、管理员处理和短时撤回规则由[评价规格](../spec/academic-content.md)维护。

已确认与延期的范围见[业务清单](business-decisions.md)。会员、奖励和价格由账务规格及运营配置管理。移动端签名、商店账号、HarmonyOS SDK 和 ArkTS 生成器在恢复对应端开发时验证。

SSO 的旧会话处理与维护窗口由迁移任务解决；容量、SLO、RPO/RTO 根据实际业务和基准测试确定。业务 API、真实登录和生产 Registry 性能仍未验收。三个应用镜像的本地构建与隔离组合已通过。Web/Admin 框架构建与联调结果由框架工作记录单独维护。
