# StuHelper Next 重写路线

## 目标、范围与进度

进度：进行中。工程基础、模块边界与业务规格已建立，可运行框架见[框架工作记录](framework-bootstrap.md)，工程检查见[检查指南](../guide/repository-checks.md)，已确认的旧业务与货币设计见[业务整理记录](business-design-extraction.md)；SSO 与业务实现尚未交付。Next 是重构版本的过渡名称，后续改名与旧仓库退役仍待迁移完成后单独执行。

## 当前交付安排

当前只推进 Web 和 stuhelper-admin，完成已确认的校园业务及模块协作。微信小程序、Android、iOS、HarmonyOS 与独立社交模块暂时搁置，重新启动时另定实施计划。后续端的参考设计继续保留。

| 阶段 | 成果 | 完成条件 |
| --- | --- | --- |
| 文档迁移 | 公共业务规格、私有模块文档、仓库边界和来源覆盖 | 已确认或明确延期的事项均有维护位置，全部文档检查通过 |
| 身份与工程基础 | 独立 SSO、模块接口、资格与权限、Web/Admin 基础 | 保留既有身份，模块依赖和停启行为通过验证 |
| Web/Admin 业务实现 | 评价、资料、目录课表、群管理、查询、通知、开放平台和存储贡献 | 对应规格的真实业务流程全部验证，账务与认证由私有模块对接 |
| 正式切换 | 数据迁移、兼容验证、恢复演练与生产部署 | 完整核对用户授权范围，并取得生产切换授权 |

## 旧数据迁移范围

完整保留 SSO 数据与学生认证数据，以及关联现有用户所需的最小账号映射。SSO 的账号、issuer、subject 和既有应用绑定保持连续。学生认证不清空，保留认证结果、学习经历、审核材料、申请与撤销历史。独立实名核验结果不迁移，新系统不从旧学生认证结果自动补造独立实名通过状态。

其他旧业务数据不进入新系统的迁移范围。旧课程评价、资料、互动、群与账务数据继续留在旧系统，本轮没有删除、清理或改写。正式退役的处理安排须在实际切换时另行确认。

迁移先进行只读导入、映射与差异核对，再制定切换和恢复方案。生产数据搬运由独立迁移任务执行。

## 待确认与验证限制

原生端与社交已明确搁置，不作为当前实施任务。课程评分的五个维度、导师评论推荐模板、匿名与署名、管理员处理及短时撤回重编方向已确认，具体规则由评价规格维护。业务确认及延期结果汇总在[业务确认结果与延期事项](business-decisions.md)，完整规则在各规格维护。会员、奖励与价格通过私有账务规格及后台配置管理。移动端签名和商店账号、HarmonyOS SDK 环境、ArkTS 生成器能力尚未验证。

SSO 的旧会话处理与维护窗口由迁移任务解决；容量、SLO、RPO/RTO 根据实际业务和基准测试确定。业务 API、真实登录、Docker build 与 Registry 网络性能仍未验收。Web/Admin 框架构建与联调结果由框架工作记录单独维护。
