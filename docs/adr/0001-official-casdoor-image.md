# 0001：独立运行官方 Casdoor 镜像

## 背景与决定因素

项目重写需要保留现有 SSO 全部数据，以及 AI、Store 等系统的账号绑定。身份服务需要能够在主站停止或升级时独立运行，并降低长期维护上游定制的成本。

## 决策与确认依据

采用未经修改的官方 `casbin/casdoor` Docker 镜像，固定官方版本与 digest。SSO 使用独立配置、数据存储和维护入口；业务系统通过 OIDC 与官方 API 接入。品牌与登录策略使用官方配置能力。

确认依据：项目负责人于 2026-10-23 在本次任务中明确要求“casdoor，就按你说的建议，用官方镜像”。这一确认决定制品形态，不代表生产已迁移，也没有指定立即停机窗口。

## 备选与取舍

官方 release 二进制可以使用其适用版本中的内置升级按钮，但本项目选择镜像带来的可重复部署与制品固定能力。维护源码 fork 会持续增加补丁、构建和消费者兼容成本，因此退出本项目维护范围。

## 后果与验证

本项目不构建 Casdoor 镜像。需要向 BJ1 Registry 缓存官方原件时使用自建 runner，保持 digest 一致，不注入文件或重新打包。独立更新入口需要完成备份恢复、兼容检查、切换与恢复编排，尚待实施。

数据与身份验收以 [SSO 规格](../spec/sso-compatibility.md)为准；机制见[独立 SSO 设计](../design/independent-sso.md)，实际进度见[迁移工作记录](../development/sso-migration.md)。
