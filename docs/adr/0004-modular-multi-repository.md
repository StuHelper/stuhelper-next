# ADR-0004：按业务模块采用多仓库

## 背景

重构要求可插拔、低耦合和高内聚。学生认证与学校数据接入包含不适合公开的内容，认证、账务和生产配置也需要独立的仓库访问控制。早期同仓库目录提案不能满足这些要求。

## 决定

项目负责人于 2026-10-24 明确采用按模块划分的 multi repo。各模块拥有数据、接口、版本和生命周期，依赖公开契约协作。详细划分见[模块仓库设计](../design/module-repositories.md)。

认证与实名、学校适配、账务及生产配置使用 private 仓库。群聊管理与信息查询目前保持 public。stuhelper-next 继续公开，负责人接受已有公开历史，后续具体私有设计迁往相应私有仓库。

公共模块可以组合部署，私有服务独立管理访问边界。模块拆仓不要求每个模块从第一天就成为独立微服务，也不允许通过共享内部表恢复隐式耦合。

## 影响

模块仓库单独维护规格和检查，公共仓库维护跨模块架构与对接目录。旧同仓库路径和 SSO 工具位置随本次文档迁移更新。业务实现与生产迁移仍按独立任务验收。
